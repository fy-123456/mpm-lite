## 范围及验收约定

沿用上一轮共同切换快照、固定运动空间、完整质量与新旧分界公共细分 Gauss 5。先对 grid 17/33 的不切换、未增强切换和余量增强路径继续减半 dt；将相邻差同时满足 $E_v<1\%$、$E_F<1\%$、$E_P<1\%$ 作为阶段门槛。分别以细时间步的速度质量范数、$\|F-I\|$、$\|P\|$ 归一化。相邻差门槛不是严格真误差上界。

初始位置和速度仍使用上一轮保存的 t=1 ms 快照，释放到 t=4 ms；不重新生成另一份更光滑的初态。候选从 dt=.03125 ms 开始，每档减半；每条路径最多先尝试五次减半，若尚未通过则如实记录，不自动宣布收敛。随后在同一历史上增加空间参考分辨率并核对其时间误差。只有当参考变化显著小于方案差异、且可靠误差集中在切换区时，才进入局部模式试验。

## 实现与时间收敛

开始时系统盘约 5.4 GiB、数据盘约 29 GiB，未触发 2 GiB 迁移或合计 5 GiB 暂停阈值。沿用每步容量守卫，仅保存场系数和数值日志。

新增相同 trial 的本构结果复用；提交时检查有限性和 det(F)>0，避免为已经求过的接受状态再次计算应力。新增与原实现的多步对照，确认位置/F、速度及预算一致，同时保留非法提交拒绝检查。

细网格参考原来的稠密三维质量分解成本较高，已加入笛卡尔参考专用的精确张量质量分解：$M_r=M_x^{free}\otimes M_y\otimes M_z$。这保持完整一致质量，仅以三个一维因子的运算替代三维稠密因子；材料势能、L-BFGS 和时间离散不变。它只用于未增强规则参考，不用于任意余量空间。三档参考的采样质量与张量质量相对差均低于 1.4e-14。

张量质量与原稠密因子、三步轨迹对照已通过。另验证可选 GPU 双精度本构：25.6 万个非均匀状态的能量/应力相对差约 1.93e-14 / 1.80e-14；包含零应变、90° 转动、随机变形、非法 Jacobian 拒绝以及四步轨迹的专项测试通过。GPU 只评估同一 Hencky＋纤维能量/应力；梯度、质量、约束、优化器和提交仍沿用参考公式。

完整 grid 65、dt=.015625 ms 的 192 步轨迹也已与上一轮 CPU 结果核对：x/F/P/v 相对差分别为 8.1e-15 / 3.9e-14 / 2.1e-13 / 2.2e-13。结果见 [backend-check.json](results/refinement/v1/backend-check.json)。CPU 首轮回归通过后，增加张量质量对非精确采样的拒绝测试，并在可访问 GPU 的环境完成最终全部 44 项测试，0 失败、0 跳过，见 [tests.txt](results/refinement/v1/tests.txt)。

## 是否进入局部增强

局部增强的进入条件预先设为：候选与参考均满足时间三指标 1%；最后两档空间参考的 x/F/P/v 差均低于增强/未增强场差的 1/10；增强相对参考的 F 误差平方超过 50% 集中在占体积 25% 的切换区。这里 1/10 是本轮对“显著小于”的操作性定义，50% 是局部化研究门槛，不是理论定理。若条件不满足，本轮不新增局部自由度。

对每个物理量 f，量化参考不确定性与方案区别的比例：

\[
R_f=\frac{\|f_{81}-f_{97}\|_V}{\|f_{enriched}-f_{shifted}\|_V}.
\]

分母是两方案的场差，而非两项误差范数的差。结果远未满足 $R_f<.1$：

| 候选网格 | $R_x$ | $R_F$ | $R_P$ | $R_v$ |
|---|---:|---:|---:|---:|
| 17 | .855 | 4.660 | 3.896 | 1.916 |
| 33 | .948 | 2.872 | 2.846 | 3.346 |

增强相对主参考的 F 误差平方份额也没有显示强烈局部集中：

| 候选 | 夹具区（体积 12.5%） | 切换区（25%） | 其余梁体（62.5%） |
|---|---:|---:|---:|
| grid 17 增强 | 12.64% | 29.96% | 57.40% |
| grid 33 增强 | 13.69% | 27.02% | 59.28% |

因此四项进入条件中，只有候选时间门槛通过；参考时间门槛、参考变化量门槛和局部集中门槛均未通过。本轮保持已有 $\Delta u=N\Delta u_a+Ce$，没有加入 $\sum_k C_k\chi_k e$。接下来应优先降低参考时间误差，并单独做保留/消除初态界面跳变的受控对照，再决定空间加密与模式设计；这种对照必须另立协议，不能悄悄改写本轮共同初态。

## 最终数值验收与资源

25 条轨迹包含候选时间扫描 15 条、参考扫描 9 条，以及收紧容差的 1 条复查，总计 10,560 个更新步。最大残差约 1.00e-9，最小 det(F)=.995884，最大夹具速度约 2.03e-20，最大能量预算闭合差约 6.88e-22，历史 x/F 重建最大绝对差约 1.36e-11。所有已保存轨迹的数值门槛均通过。

grid 97 最细终态的 Gauss 5/7 能量、力、切线作用相对差分别为 9.8e-16 / 7.5e-13 / 1.2e-13。将独立共同探针从 Gauss 3 加密到 Gauss 5，grid 33 增强相对主参考的 x/F/P/v RMS 变化均低于 3.83e-9。共同汇总探针为 874,800 个；这些检查与容差复查、CPU/GPU 轨迹核对一起，支持此次数值比较的有效性，不能替代尚未通过的参考精度门槛。

保持原求解方程的计算优化使后续加密可执行：同一 grid 65、dt=.015625 ms 路径，本轮耗时约 72 s，前一实现约 890 s；这是本机诊断运行的组合改进，不是独立 GPU 性能基准。最小时间步的 grid 65/81/97 参考分别约 219 / 406 / 762 s，任务曾并行执行，不能把各任务墙钟时间相加当作总耗时。所有参考仍使用 Gauss 5，材料点数分别为 256,000 / 500,000 / 864,000，未进行历史或材料采样压缩。

结束时系统盘约 4.97 GiB、数据盘约 31.57 GiB，合计约 36.54 GiB。每步检查容量，未触发低于 2 GiB 的迁移或合计低于 5 GiB 的暂停；原始字节数保存在结果中。

## 初始历史的界面诊断

对同一保存的初态，在七个旧内部 x 界面两侧取 $X_x\pm\epsilon$，对横截面做面积加权 RMS，检查位置、F 以及参考牵引 $Pn$（$n=(1,0,0)$）。当 $\epsilon$ 从 1e-7 减为 1e-8，位置差从约 2e-7 缩小到 2e-8；F 差稳定在 .002469–.002525，牵引差稳定在 .4863–.5823。

这量化了共同初态的位置连续、梯度分片特征。它提示应单独分析初始历史界面跳变对细参考收敛的影响，但本轮没有通过额外受控实验证明它解释了全部空间差异，也没有平滑或改写原初态。数据见 [initial-traces.json](results/refinement/v1/initial-traces.json)。

## 复现命令

以下命令均在仓库根目录运行。先完成时间扫描，再计算三档空间参考；参考任务彼此独立，可按本机设备安排并行。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m benchmarks.aniso_refinement --stage time
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m benchmarks.aniso_refinement --stage solver
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m benchmarks.aniso_refinement --stage reference --reference-grid 65 --device cuda:0
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m benchmarks.aniso_refinement --stage reference --reference-grid 81 --device cuda:1
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m benchmarks.aniso_refinement --stage reference --reference-grid 97 --device cuda:2
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m benchmarks.aniso_refinement --stage analyze
```

省略 `--device` 时使用 CPU 本构。运行会校验配置与初态指纹，复用已经通过验收的同配置轨迹；改变设备配置会重新计算对应轨迹。GPU 阶段只需要项目已有的 Warp 依赖，本轮未安装新依赖。

```bash
ANISO_TEST_CUDA=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m unittest tests.test_aniso_refinement tests.test_aniso_convergence_reference tests.test_aniso_residual_enrichment tests.test_aniso_history_increment tests.test_aniso_consistent_transfer tests.test_aniso_template_remap tests.test_resource_guard -v
```

不设置 `ANISO_TEST_CUDA` 时跳过可选设备专项。原 `recover()` 严格兼容检查、生产默认和求解器算法均未改变；本轮优化用于研究原型。
