1. `engine/aniso_phase1/research_observable_boundary_next/rt0.py::CartesianTopology` 限制总单元数≤32；`research_stabilization_boundary_next/local_geometry.py::partition` 另有限制x-only且≤32。两处含义不同，不能只删其中一个判断。

## 3. 方程、比较口径与验收尺度

### 3.1 本轮不得改变的物理关系

位移、体积与体积梯度为：

\[
u(X)=\sum_a\Phi_a(X)q_a,\qquad F=I+\nabla_Xu,
\]

\[
V_c(q)=\int_{\Omega_c}\det F\,dX,\qquad
G_{c,a,i}=\sum_{p\in c}w_p\sum_j\operatorname{cof}(F_p)_{ij}\partial_j\Phi_a(X_p).
\]

固定基底下，沿线性q路径，cofactor是路径参数的二次多项式。因此B采用：

\[
\bar G=\frac{G(q_n)+4G((q_n+q_{n+1})/2)+G(q_{n+1})}{6},
\qquad\bar G:\Delta q=V(q_{n+1})-V(q_n).
\]

这条离散链式关系是固体压力功与流体体积功相消的依据；三维重排和性能优化都必须保留。

\[
C\Delta p+\alpha\Delta V+hBz=0,
\qquad H(F)z-B^T\bar p+g_b=0,
\qquad\bar p=(1-\theta)p_n+\theta p_{n+1}.
\]

其中 `C=storage × diag(V0)`，继续使用参考体积定义；H积分包含完整的 \(F^T\mathcal K^{-1}F/\det F\)。固体压力项为 \(-\alpha\bar G^T\bar p\)。H为SPD不代表完整混合系统为SPD，继续使用已验证的缩放一般LU和原系统真实残差。

\[
E=\tfrac12v^TMv+U_{\rm material}+U_{\rm stabilization}+\tfrac12p^TCp,
\]

\[
D_D=hz^THz,\qquad D_N=(\theta-\tfrac12)\Delta p^TC\Delta p,
\qquad\Delta E+D_D+D_N-W_{\rm boundary}-W_{\rm external}-W_{\rm source}\approx0.
\]

源项本轮为0，但账本仍保留该字段。θ切换后新步的Dnum可为0，已经累积的启动Dnum不能清零。很小的收支缺口说明离散方程内部一致，不直接证明空间真解准确。

### 3.2 粗细压力网格的可比关系

用 `Rp` 对细压力做参考体积加权平均，`Rm` 汇总广延量，`Rz` 按方向汇总有向面积积分流量。检查：

\[
R_p\mathbf1=\mathbf1,\quad R_mV_{0,f}=V_{0,c},\quad B_cR_z=R_mB_f.
\]

RT0延拓 `Ez` 必须把粗单元的线性法向场积分到细面，不能用 `Rz.T` 冒充。固定同一个q时，再验证：

\[
R_zE_z=I,\qquad H_c\approx E_z^TH_fE_z,
\quad V_c\approx R_mV_f,\quad G_c\approx R_mG_f.
\]

这些是相同变形、粗RT0子空间上的算子关系。真实粗细轨迹的q已经不同，不能要求它们逐时刻满足上述相等式，应比较共同物理位置上的场与守恒量。

工程流量与反力按时间积分比较：

\[
\bar z_k=\frac{\sum_{n\in k}h_nz_n}{\Delta T_k},\qquad
\bar R_k=\frac{\sum_{n\in k}I_{R,n}}{\Delta T_k}.
\]

这里 `IR` 是原始反力冲量。端点压力、位移与速度取同一物理时刻。面流量的单位已经是m³/s，不再乘面积；累计排水保留六侧方向。

### 3.3 实用验收，不追逐机器极限

工程误差采用原有权重与单位，预算为 \(e\le a+0.05\|y_{\rm ref}\|\)：

| 量 | 绝对下限a | 必须报告 |
|---|---:|---|
| 压力 | 0.001 Pa | 体积加权范数、最小值、边界附近分布 |
| 含量/累计排水 | 1e-10 m³ | 储水与αΔV合计、总量、六侧分量 |
| 工程面流量/六侧流量 | 1e-10 m³/s | 区间均值、方向、限制后的空间差 |
| 位移 | 5e-5 m | `x-X`，共同探针与场形状 |
| 速度 | 1e-4 m/s | 同时刻与主要变化趋势 |
| 骨架/总PK1、Cauchy及纤维应力 | 0.02 Pa | 全场、夹持区、过渡区、内部区分别比较 |
| 反力 | 1e-4 N | 同区间原始冲量，不能只看最终合力 |

这些绝对下限可能大于当前纳米级位移等弱响应。因此还要展示实际信号幅度与误差幅度；若预算盖过了信号，只能称“未发现工程异常/差异低于当前关注尺度”，不能借此宣称5%相对空间精度。

同一输入的新旧实现等价继续沿用BASE对应量的代数预算，通常为 `atol + 2e-5 × 参考范数`；atol必须按已存在比较器的单位逐项冻结，不能用一个无单位数比较V/G/H。H比较Pa量纲的作用结果，G比较指定长度方向下的体积变化与压力功。场景5%预算不用于放过索引、漏项或恢复错误。

硬条件：有限值、原始带单位残差通过、`det F>0.1`、本场景压力非负检查、完整状态与账本提交一致。沿用累计质量1e-10 m³与累计能量 `1e-9 J + 1%×|窗口初始能量|` 的实用口径，同时保留每步压力功和能量检查。上轮约1e-18 m³和1e-17 J的测得缺口不是新的强制精度目标。

### S3：独立固体参考与144函数优化进入条件，4步

- **为什么：** 只有新增空间上的真实平衡解才能估计固体表达误差；投影/插值没有重新平衡，不算新参考。
- **如何验收：** 真实残差、边界、minJ、能量/反力正常；报告R0/R1/R2逐区域差及积分差。相邻最细参考差目标≤工程预算1/4，且主要误差总体缩小；不强迫所有区域严格单调。若预算内不足以分辨，保留参考受限，不追加无限加密。交付 `S3/solid-reference-comparison.json`。

### S4：根据新热点尝试一个性能候选，4步

### S5：资源失败下的恢复语义，3步

**S5.1｜分离已提交状态恢复与设备物理重验。**

- **做什么：** 在新适配层保留一份已完整验证、已持久化的提交状态；失败后先丢弃试算与设备缓存，再通过文件哈希、身份、形状、有限值和历史连续性认证提交对象。设备几何重验仍在下一次真实推进之前执行。若CUDA上下文已不可用，则退出并交给新进程恢复，不强行承诺进程内继续。
- **为什么：** BASE已表明显存短缺时调用旧restore做几何重验也会失败；需要避免把“恢复最后一次已提交值”和“申请设备资源重算”绑死。
- **如何验收：** 明确 `restored_pending_device_validation` 与 `ready_to_advance` 等不同状态，后者必须通过完整原验证；仅允许恢复先前已认证、未被修改的提交值，不能藉此接纳新状态或跳过物理检查。交付 `S5/recovery-contract.json`。

**S5.2｜用受控故障验证，不制造真实显存争抢。**

- **做什么：** 在受控分配入口注入一次资源拒绝，检查提交指针、所有流固字段、累计账、随机/时间身份与帧输出；解除注入后重验并重算一步，与正常保存轨迹比较。另做只读坏哈希/错误模型拒绝检查。
- **为什么：** 重现语义即可定位恢复问题，不需要占满GPU或影响外部任务；单看q不变不足以证明事务安全。
- **如何验收：** 失败无新提交、无错误帧，恢复按合同返回，正常重算等价；坏来源被拒绝。故障尝试和重算分别计数。交付 `S5/resource-fault-check.json`，并注明真实驱动故障与外部持续显存饥饿未被该注入全面覆盖。

**S5.3｜保留原保护并接通新入口。**

- **做什么：** 不改原70%初始空闲显存保护，不终止其他任务；将恢复入口、待重验状态和错误日志接入本轮研究CLI。若新语义难以可靠分离，则保留已证明可用的新进程恢复，明确进程内分支受限。
- **为什么：** 降低保护标准只能掩盖资源问题；持久化可恢复与进程内恢复是不同能力。
- **如何验收：** 新进程可只读认证并加载最后已提交状态，且未验证前不能推进；记录适用范围，不将无法保证的恢复行为写为通过。交付 `S5/recovery-scope-decision.json`。

**S6.1｜运行有针对性的最小回归。**

- **做什么：** 覆盖非连续索引/伴随、构造内存、缓存所有权、压力功、限制/延拓、恢复和来源拒绝等被本轮改动触及的合同；利用S2/S4/S5已有真实运行作集成验证。只读加载继承日常252步终态和其质量/规则身份。
- **为什么：** 不重复长周期或未受影响测试，但也不能用“误差不严”免除索引、守恒与事务检查。
- **如何验收：** 报告实际执行命令、退出码、唯一测试数、继承项、失败项和源码哈希；不为达到测试数量另造镜像实现测试。交付 `S6/test-report.json`、`S6/default-scene-decision.json`。

**S6.2｜更新可视化与运行说明。**

- **做什么：** 最多6个新增物理帧：粗/细各25、50、75微秒，另用曲线展示h/half与故障结果。展示同尺度压力截面、位移、区域应力、六侧流量和能量分账；可复用继承日常12帧动画，但标注来源与位移放大倍数。
- **为什么：** 总量守恒不能排除局部条纹、错向或切面错误；实际物理幅度与演示放大也必须区分。
- **如何验收：** 图像可加载、数据来源可追、色标/位置一致、时间标签正确；至少人工查看关键场图。HTTP资源检查与浏览器交互测试分开报告，不把前者冒充后者。交付新 `index.html`、诊断图、实际已验证的CLI说明。

**S6.3｜逐步结案并封存新发布。**

- **做什么：** 将27步逐一绑定证据，区分通过、受限、未触发、失败及原因；封存输入、源码快照、结果、文档和能力清单，再通过包含BASE的完整祖先审计。
- **为什么：** 后续必须能识别哪个版本、哪段时间、哪种网格真正通过，不能再靠文档名字判断最新实现。
- **如何验收：** 新发布直接父SHA为开工复核的BASE；旧源码/文档哈希不变；新结果与当前源码完全绑定。分别声明 `implementation_equivalence`、`engineering_spatial_consistency`、`solid_static_reference`、`resource_recovery`、`exclusive_performance`，不合成一个不分范围的“全部正确”。交付 `release.json`、`requirement-audit.json`、`capability-matrix.json` 及新进度文档。

## 6. 预算和进入条件

| 阶段 | 正常工作量 | 上限及说明 |
|---|---|---|
| S0 | 审计、冻结 | 0动态步 |
| S1 | 四网格拓扑；主要32/128静态GPU几何 | 最多12组新大规模静态算子检查；CPU参考优先复用，确需重算最多2组；无动态步 |
| S2 | 两格各18步＋一次故障/重算 | 基本38次动态尝试；可选细格h/2再36次，另留4次已定位修复/资源恢复余量，合计≤78 |
| S3 | 一条参考加密路线 | 最多2个新增参考级、4次新非线性平衡；无新动力学/空间训练 |
| S4 | 一个候选 | 条件触发后4个对照单步＋入选后4连续步，≤8动态尝试 |
| S5 | 一次受控资源故障与重算 | 通常2次，含修复余量≤4动态尝试 |
| S6 | 继承默认只读加载、展示、封存 | 0动态步，不跑252步旧长周期 |

全轮动态尝试硬上限 **90**；基础无性能候选、无时间加密时约40次，包括失败与重算。失败不能从尝试数中删除。构造失败不算动态步，但记入进程总耗时与失败记录。静态求解与算子调用另计，不塞进动态步统计。

资源默认上限：新结果和可重建缓存合计3 GiB、峰值RSS16 GiB、新增几何元数据不超过 `min(256 MiB, 2%×初始空闲显存)`；额外工作缓冲先登记并纳入全模型显存保护。CPU参考/静态求解合计1800秒，GPU相关完整进程合计1200秒；小型CPU合同测试另计。先做预估，超限时缩减候选或把该分支标为受限，不能悄悄提高上限。

若128格几何受限，停止S2依赖分支；S3可继续独立参考，S4可针对原认证32格B，S5可验证原安全范围恢复。若仅参考精度不足，保持正式空间并继续独立性能/恢复工作。若发现共同压力功、质量或原势能错误，先定位其影响范围，再暂停依赖该问题的分支。

每个阶段结束、出现异常或改变预登记选择时更新新进度文档，至少写“已完成、证据、当前限制、下一步、累计预算”。不改写封存历史记录。

## 7. 异常处理与停止判据

| 现象 | 分析与行动 | 可以继续的范围 |
|---|---|---|
| 索引/转置/方向不一致 | 用小型非对称输入定位，修复后只重验受影响项 | 通过后恢复原计划 |
| 显存分配超限 | 核对整域权重副本、元数据、临时伴随与外部占用；不降保护、不杀外部进程 | CPU参考或安全原网格 |
| 非有限值、负压力、minJ失效 | 对照基线同一步、原始残差、压力功和边界；禁止靠加阻尼掩盖 | 仅与异常无关的分支 |
| 粗细结果超过5%工程预算 | 先分离时间误差/局部布局/边界方向，再判断空间敏感性 | 可完成受限报告，不强行通过 |
| 细参考没有逐渐接近 | 检查稳定化、材料积分、评价位置和真实残差；预算内诊断后停止加密 | 正式144空间保留 |
| 性能小于5%或噪声覆盖收益 | 保留基线，保存候选实验记录 | 继续恢复及交付 |
| 故障后状态或累计量变化 | 视为事务错误，禁止发布该恢复路径 | 继续使用认证持久化新进程恢复 |
| 原因难以定位且修复有风险 | 保存复现输入、日志、最后安全提交、已排查项及缺失证据，限制该分支 | 不依赖该问题的任务继续 |

一般小问题、根因明确的实现问题应自行修复，不因一次失败就跳过。潜在风险涉及物理含义、未认证状态、丢失交叉项或来源绕过时，必须先深入分析；不能用放宽容差或更改问题定义替代定位。
