# MPM lite 最新基线下的单进程顺序优化计划

本文基于2026年9月30日重新核验的本地源码与成果，规定后续实施步骤。**本次仅编写计划，没有修改实现、依赖、旧协议或成果，没有运行项目测试、仿真和性能实验。** 文中的新增文件、执行步骤及验收均为未来工作。

执行方式从五组并行改为一个执行进程按 S01—S12 顺序处理；阶段完成并封存后才进入下一阶段。允许 float64 和 Warp，CPU float64 作为数学与数值对照。首先修复动力学数学基础，再稳定空间与参考，随后开展完整动力学、压缩、GPU及二维耦合接入。

## 2026年9月30日开工调整

用户已授权按本计划实施，并明确以场景正确性和稳定性为先，不要求大量帧或过严数值实验。本轮采用`practical`协议：保留来源、数学适定、合法F、边界、真实残差、能量和事务硬检查；材料/后端差分采用工程容差；先做少量状态、短窗和最多16步的四阶段循环。原48000步、严格空间参考、完整消融/泛化和独占性能认证保留为未来目标，不把本轮轻量验证写成这些目标已完成。

仍按S01—S12顺序推进。当前空间精度问题已有明确证据，本轮先保留144函数物理空间并修复坐标冗余，不扩大参考网格。明显异常先定位根因；已定位的小问题自行修复；不能可靠定位的风险路径单独标记并跳过，其余可独立步骤继续。实现与原封存代码分离，新增代码在`research_sequential`命名空间。

## 2 顺序执行与版本约束

### 2.1 单进程规则

1. 常规阶段在同一执行进程内顺次调用，`workers=1`；不使用进程池，不同时运行A/B/C/D/E，不保留后台候选或自动后处理队列。
2. 下一项工作只能读取上一项已完成并封存的输入。当前阶段发生异常，记录拒绝原因、最后已提交状态和资源情况后停止，不能自动跳过硬验收。
3. 算例、预算、积分阶次、时间档和性能重复均逐个运行。初始CPU数值库线程设为1；若后续调整内部线程，作为单独运行配置登记。GPU可作为该进程的计算后端，不另开并发研究任务。
4. 先检查是否存在旧研究后台任务；有活跃任务时记录并等待资源，不能擅自终止其他工作。正式性能测量须取得实际独占资源。
5. 真正冷启动需要新运行上下文时，先封存状态并退出，再串行重启执行进程。若要求全程保持同一进程、不重启，则仅报告一次真实冷启动及进程内重复，多个独立冷启动结果标记未认证；不能用暖缓存重建冒充全冷。

### 2.3 阶段状态与停止规则

每个阶段统一记录`not_run / running / passed / failed / limited / blocked_resource`，并附输入、源码、协议和成果摘要。不能仅凭退出码或测试数量设置物理能力通过。

- **硬门槛**：来源一致性、数学适定、有限值、合法F、正确约束、精确导数、守恒和事务。失败即停止依赖阶段。
- **研究精度目标**：空间2%/1%、参考认证和性能收益。未达时按预登记预算继续；预算耗尽后可封存为`limited`，明确保留失败状态。数学正确的固定离散模型仍可进入实现/时间研究，但不能声明空间精度已通过。
- **资源不足**：停止对应长作业并保存检查点，不用缩小模型、减少积分或缩短终点替代目标。先优化数学等价实现或调整已登记资源。
- **模型改变**：空间、Ks定义、质量、材料、边界或时间方程任一变化，建立新身份并重验受影响步骤。S06之后换空间，必须返回S03/S06，不继续沿用旧循环结果。

### S02 推导并选择零惯性问题的修复路线

**前置条件：** S01通过；使用当前冻结144局部函数空间作为诊断对象。

**做什么：**

1. 读取C已保存的三条零方向，独立复核物理重建T、自由质量Mff、原Ks、边界固定行和力对偶；区分自由依赖与域外约束零行。
2. 在自由坐标写出`q_f = R r + N z`，其中N覆盖物理零空间、R覆盖独立运动方向。逐项检查`T S N≈0`和`M S N≈0`，S为自由注入；完整位移为`u=S q_f+L(t)`。
3. **优先评估能量一致的代数消元。** 原材料势能不依赖z时，由原总势能的`∂U/∂z=0`求z。对现有二次Ks，检查`NᵀSᵀ K_s S N`可逆性，推导z对r及边界提升的依赖、有效稳定化和反力；Ks在此表示完整分量空间中的对应嵌入。
4. 若无法证明消元合法，另行制定含代数约束的动力学方程、初值一致性、残量、切线及约束处理。只选择一条主路线继续；另一条保留分析，不同时实施两套求解器。
5. 新表示显式记录独立坐标、代数坐标及原完整系数恢复。当前216标量运动秩只适用于本空间，不硬编码为今后所有候选的尺寸。

**为什么：** 三条方向没有物理位移和惯性，却具有稳定化能量，简单删除系数会改变势能。普通满秩质量ODE构造器也不能直接承担代数约束问题。

**产出：** `nullspace-review.json`、数学推导说明、映射原型、路线选择记录及拟用方程身份。

**如何验收：** 独立SVD与质量谱一致；阈值变化不改变结构性判断；零方向上的Ks能量被保留或按推导消元。消元路线需证明在代数平衡流形上势能及力等价，不能要求任意未平衡z状态与消元状态同能。代数路线需给出一致初态与可解性证据。两路线均不得加人工质量、任意对角移位或静默修改Ks。

**失败处理：** 若两路线均未证明适定，停止依赖动力学实施并交付结构诊断。改变稳定化物理模型必须另立明确模型版本及比较，不能冒称原模型无损修复。

### S03 验证新表示的静态与动力学数学基础

**前置条件：** S02选定且推导明确。

**做什么：**

1. 实现新坐标到完整位移/速度的映射与伴随，检查x=X+u、F=I+grad u及状态/方向的边界提升。总位置仅加一次参考坐标。
2. 对零夹持、原0.005 m快照及多个有效扰动，比较原模型与新表示的静态平衡、能量、完整反力、探针应力和边界功；分开材料与Ks贡献。
3. 重新计算保留载体—局部及自由—夹持交叉项的质量。检查独立运动质量的秩、条件数、动能及五/六阶一致性；代数方案另外检查约束残差与整个线性化系统。
4. 对精确物理切线做导数、伴随、对称性检查，再求广义模态和敏感方向。预条件与搜索曲率不能替代精确切线。
5. 检查边界提升变化和完整速度恢复，推导新坐标下的边界冲量及功，不能直接照抄旧Mff逆公式。

**为什么：** 修复质量只解决一个条件，还可能影响稳定化、反力、时变约束和模态；这些都必须在长循环前确认。

**产出：** 新表示静态对照、`mass-and-modal-audit.json`、导数扫描、边界功与冲量检查。

**如何验收：** 通过总表数学门槛；静态等价比较使用共同物理场和相同势能定义。广义特征残差建议≤1e-7；无未经解释的新增零模态。正质量子空间和刚度稳定性分别判断，微小零附近负舍入值不能称真实负质量。物理负曲率不能用SPD假设掩盖。

**失败处理：** 按映射、消元、质量、Ks、边界分别定位，回到S02修正推导；在新表示未通过前，不运行真实动态短窗。

### S04 建立预算内可认证的空间参考

**如何验收：** 满足总表参考工程门槛；至少两个逐级差异下降。候选主要精度研究沿用其原二次静态势能；有限变形空间精度必须另有相同非线性势能的平衡参考，不能拿线性参考直接相减。

**失败处理：** 超资源上限即停止该路线；可改用数学相容的局部加密或矩阵自由实现。只有部分区域可靠就只认证该部分；不能删去难区、换物理域或放松夹持来取得通过。预算内仍不足时标记`reference_unverified`，后续只允许有限离散模型研究。

4. 在相同初态、质量、边界、Ks、时间档、算法和求解容差下，先短窗、再与S09对应的完整循环比较；唯一变化是材料积分规则。

**为什么：** B在原共同空间上的静态认证不自动覆盖新空间和动态路径；局部敏感切线是现有四阶规则的主要失败来源。

**产出：** 新压缩规则、隐藏验收、真实B/C事务、完整循环增量误差和成本分账。

**如何验收：** 静态执行1%/2%预算，动态增量执行预登记1%目标，且两条轨迹各自满足C判据。质量规则和作用必须保持相同，不能仅比较总质量。近零误差尺度固定，单元/分区失败不能被全域抵消。点数减少不等于动态加速，只有总成本下降且超过测量波动才记录性能收益。

**失败处理：** 候选失败则升阶或采用预先固定的同源局部充分规则，再建立新候选/隐藏批次；不改dt来抵消压缩误差。压缩收益不足可以保留充分积分作为主实现，GPU阶段仍以充分积分路径为独立对照，压缩能力保持未认证。

### S11 接入GPU并完成公平成本验证

**前置条件：** S09充分积分CPU方程与轨迹冻结；压缩GPU分支还需S10通过。

**做什么：**

1. 复用[D现有GPU空间与算子](../engine/aniso_phase1/research_d/stage2/gpu_operator.py)，先适配S06的最终坐标、可能的代数恢复和有效稳定化，再做同状态CPU/GPU位置、F、伴随、能量、完整梯度和精确切线对照。
2. 在共同初态和边界下独立求静态平衡。检查状态绑定的对称性和曲率，只有通过SPD资格的子问题用PCG；其余使用适当一般或对称不定策略。预条件和搜索曲率单列，不改变原势能。
3. 依次比较CPU充分、GPU充分，再在S10通过时比较CPU压缩、GPU压缩。动态接入完全使用C已冻结方程、时间步、边界功、残量、代数约束和事务，不另造时间模型。
4. 对GPU先运行一步、故障回滚、短窗，再运行对应完整周期；保存相同物理时刻原始字段。异步计算在判定残差、提交和计时前显式同步。
5. 正式计时包含父/子包验证、映射、材料布局、JIT、CPU/GPU各自搜索矩阵与预条件构造、传输、求解、输出及回退。原D的CPU/GPU共用GPU搜索矩阵结果仅作历史复用诊断；完整CPU基准必须自行构造其所需对象。
6. 在独占条件下串行进行至少3次真正冷启动和至少5次暖重复，记录AB/BA顺序、A/A波动、内存/显存和原始样本。冷启动依2.1节串行重启，不启动并行worker；严格不重启模式则冷启动重复认证留空。

**为什么：** 当前D证明的是原144空间有限静态范围的正确性；新空间与动力学必须重新接入。原71.638 s矩阵构造只测一次，不能由0.508 s暖解外推完整任务收益。

**产出：** 最终空间GPU静态/动态验收、适用曲率与预条件表、完整冷/暖成本、采用范围和失败回退记录。

**如何验收：** 同状态满足总表GPU门槛，两端均达到同一真实残差；完整周期、各阶段及终态满足后端与时间判据，状态提交一次且失败回滚完整。性能只有达到预登记收益和波动条件才晋级；构造、初次编译或不利场景不得省略。

**失败处理：** 某后端/某状态失败，保留对应CPU充分路径并标记范围受限；无正式性能收益也可以封存正确GPU研究实现。不能通过降精度、松残差、省诊断或换物理问题制造加速；生产默认切换不由本计划自动执行。

### S12 完成二维最小接口接入并封存整体交付

**前置条件：** 最终公共合同固定；E已有独立二维物理交付可恢复。动态GPU或压缩若未通过，不作为E二维验证的必需能力。

**做什么：**

1. 在最终合同版本下重新消费E混合算子包。当前E记录绑定的D合同SHA为dc393bab开头，当前D最终合同为b5182c56开头；保留旧证据并生成新子证据，不覆盖旧E清单。
2. 将E实际二维Q2位移、RT0流量、P0压力系统接入真正的混合求解后端。明确边界消元、块单位、dt缩放和压力规范；精确消元RT0时必须恢复流量并检查原三块残差。
3. 原混合矩阵不是自动SPD。一般系统采用合适的一般求解器；MINRES需先有等价对称化和适当预条件，不能直接套固体PCG。不得通过人为增储水或加压力惩罚消除困难。
4. 将E作为独立二维子任务接入统一事务协调器，使用纯值提案和一次发布；覆盖父拒绝、过期、异常、双提交、错误恢复和重试。此处复用C事务机制，不把二维准静态Biot状态拼进三维固体位移，也不把C固体惯性加到E原方程。
5. 复验一维固结、二维制造解、压力模式、36工况及既定敏感子集。总/有效应力同时输出完整平面应变3×3张量，中心、积分均值和全场口径分别验收。
6. 保持E独立加载：0—0.4 s线性加载、0.4—0.8 s保持、0.8—1.2 s卸载、1.2—1.6 s末保持；dt为0.04/0.02/0.01/0.005 s，分别40/80/160/320步。不能套用C固体的余弦边界。
7. 最终生成S01—S12统一能力矩阵、全部输入/源码/数据清单、失败及未执行列表、独立复载和恢复记录。逐项标记空间、时间、压缩、静态GPU、动态GPU、二维耦合与性能状态。

**为什么：** E的独立物理验收已通过，但D最终合同与实际求解后端消费还缺证据。整体发布必须把接口成功与新增物理能力分开。

**产出：** 新E最终合同消费、真实求解器及事务验收、二维完整物理回归、联合交付清单和复现说明。

**如何验收：** 压力/位移/各分区有效和总应力执行4%门槛，循环执行5%门槛；质量、真实残差、外功、Darcy耗散和后向Euler数值损失分别通过。11类既有事务控制继续保留并增加真实后端故障注入。高对比稳健性通过不自动成为解析精度通过。最终清洁副本能核验来源并复算必要控制，旧包摘要保持不变。

**失败处理：** 合同拒绝先修显式适配器，物理量超限先修残量/评价/求解，不扩大到三维移动或有限变形全耦合。E最小接入通过只说明同一执行框架消费二维方程及事务；真实C惯性与E孔弹性的联合物理方程仍需另立推导和阶段验收。
