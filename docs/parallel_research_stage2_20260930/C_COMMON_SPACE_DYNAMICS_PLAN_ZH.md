## 本轮模型与边界

主要结论限定为同一冻结空间的参考连续体点惯性和充分材料积分。固定参考基使 M 恒定；粒子位置变化并不使本模型质量几何相关。没有独立 APIC 微惯性，局部自由度的速度和历史必须保存。质量积分与 B 的材料积分独立，不能因材料压缩改变惯性。保留全部局部自由度，不沿用 v20 针对其他模型的不可见方向消元，也不作默认静态消元。

主动态状态采用完整位移 `q_full=S q_free+L(t)` 与完整速度 `v_full=S v_free+Ldot(t)`。`S` 是冻结自由注入，`L(t)` 仅在约束行非零。状态求值加入当前 lift，方向、JVP 和自由 Hessian 作用使用零 lift。现有 `CommonSpace.response` 的默认固定 0.005 m lift 必须通过 C 的私有适配器显式处理；不能在每步换时钟却保持同一静态边界。

主循环从另立并验收的零夹持动态初态开始：在相同空间、势能及充分积分下检查或求解零夹持平衡，初速度为零；是否无应力由实际应力和残差确认。原静态快照保持原样，另可用于已加载保持短窗，并明确属于另一初值问题。任何新的动态初态和加载协议均进入子交付清单。

## 执行步骤

### C1 固定来源并建立新增能力清单

**做什么：** 通过严格加载器验证父共同包、真实源码副本和输入链接目标；保存 657／1107 自由度、原稳定化、质量规则、材料规则和方向场指纹。建立“第一阶段已通过／本轮新增／本轮不声明”矩阵。将当前已有 `PointInertia`、`CommonSpace` 和值事务作为只读依赖。

**为什么：** 防止重复实现已完成冻结工作，或把小模型、原 v20 动力学和新 A 空间的证据拼成一个算法。

**产出：** `baseline-check.json`、能力差异表、父包与新增源码清单。

**如何验收：** 所有父绑定文件一致，实际空间维度和指纹正确；未自动选择新 A 包；旧 C 小模型仍可独立解释，但不成为本任务真实性证据。

**失败处理：** 来源错误时停止依赖实验，修正副本和输入；真正需要改变空间、材料或质量模型时建立新子版本并重设验收。

### C2 定义动态初态及完整边界历史

**做什么：** 在 C stage2 中建立 `L(t)`、`Ldot(t)` 和状态展开器；主协议沿用峰值 0.005 m 的余弦加载：0—0.5 s 加载，0.5—0.6 s 保持，0.6—1.1 s 卸载，1.1—1.6 s 末保持。数值定义与现有 `carrier_driven.displacement`、`endpoint_boundary.prescribed_speed` 逐段核对，保存时间断点。另建零夹持平衡初态并保存 q、v、F、应力、残差、能量、材料规则和求解公差；原 0.005 m 快照仅作另一已加载保持案例。

**为什么：** 起点错误和 lift 的位移／速度不相容会制造首步冲量，影响末端误差并破坏四档公平比较。

**产出：** `dynamic-protocol.json`、`initial-dynamic-state.npz`、`boundary-history.json` 与初态审计。

**如何验收：** 各 dt 使用逐字相同初态；位移和速度约束在所有阶段边界相容；自由初始残差满足预登记静态门槛；F 与应力证明实际初态性质。零夹持求解结果若有预应力必须报告，不能因 v=0 就称无应力。完整 q 与自由 q 的映射双向一致。

**失败处理：** 初态未平衡则先定位势能、Ks 或求解误差；不通过丢弃首步、人工速度投影或修改原静态快照掩盖不相容。

### C3 认证完整质量秩与交叉惯性

**做什么：** 基于现有 `PointInertia.apply` 构造或分块恢复 369×369 标量质量与 219×219 自由质量，再按三分量复制语义验证完整矩阵。通过轴分解、稀疏和有界批次运算避免形成巨大稠密节点基。检查 Mcc、Mcα、Mαα、自由—夹持块，对称性、正定性、尺度化谱及五阶／六阶一致性；加入删除交叉项的反例，但不把反例用于主循环。

**为什么：** 第一阶段两个模式作用一致不等于全空间满秩；局部模式可能带来小质量特征值，交叉项影响边界冲量和真实频率。

**产出：** `mass-audit.json`、质量矩阵或可复算分块、特征谱、条件数及交叉项反例。

**如何验收：** 冻结自由空间数值秩必须为 219 标量／657 分量；秩阈值基于矩阵尺度、机器精度和独立积分误差预登记，同时报告最小特征值和误差界，不能只调用 Cholesky 成功就称已认证。建议对称相对差≤1e-10；父包原两个模式的五阶／六阶质量作用继续保留 rtol=1e-10、atol=1e-12 的原判据，不能放宽。新增全矩阵恢复及扩展方向比较可另登记相对差≤1e-8，并说明批处理与矩阵恢复误差；完整平移质量仍为 0.046875 kg。

**失败处理：** 秩或正定性异常时检查基线性相关、坐标缩放和质量实现；不加人工质量、对角正则或删除 α 以获得通过。若独立证实冻结基有问题，交 A 建新空间版本，本包保持未通过状态。

### C4 验证真实空间切线与模态

**做什么：** 使用与 B2 相同势能语义但不依赖其新实现的 C 私有适配器，保留原稳定化能量、内力及切线。对零加载平衡和归档状态做能量导数、对称性及虚功检查。用真实 Mff 和完整势能 Kff 求取低频、高频及局部敏感模态；优先采用有残差证据的矩阵自由广义特征求解，按资源允许补显式块，不盲目组装高维材料 Hessian。以小振幅模态解析解检查无传递时间推进的目标量。

**为什么：** 小模型的频率范围不能用于真实 Q4 空间选 dt；Ks 或质量交叉项遗漏会改变频率和终态响应。

**产出：** `tangent-modal-audit.json`、模态向量、广义特征残差、频率区间、原 Ks 分项证据。

**如何验收：** 能量梯度相对差建议≤1e-6、切线作用≤1e-5，适当步长区间内稳定；模态报告 `||Kφ−ω²Mφ||` 的尺度化残差，建议≤1e-7。小振幅误差随幅度和 dt 分别收缩；异常负模态先解释稳定性，不能隐藏或强行改为 SPD。

**失败处理：** 区分真实失稳、质量病态、切线错误和积分不足；只允许与原势能等价的求解预条件，不通过修改物理刚度解决。

### C5 构造完整质量下的约束冲量和反力

**做什么：** 根据完整自由／约束块推导和实现阶段边界速度修正。端点约束修正须满足 `Mff δvf=−Mfb δvb`，保留自由—夹持交叉项；完整冲量由 Mδv 求得。输出原始区间反力、端点与中点冲量、材料及稳定化反力、惯性反力、边界功和约束动能变化。通过刚体虚位移的功对偶计算总力／总矩，不直接把所有局部系数力相加。

**为什么：** 将载体或网格速度直接覆盖为夹具速度会漏记冲量和功；增强基的局部系数并非独立物理粒子力。

**产出：** `constraint-impulse-audit.json`、边界功恒等式、总力／总矩提取器。

**如何验收：** 物理夹持体积位移和速度误差建议≤1e-9 m／m·s⁻¹；自由端点冲量在预登记物理尺度下≤1e-9；端点动能变化等于边界冲量功减约束损失，并记录绝对值及相对尺度。刚体探针力矩与积分侧相符；原 Ks 的反力不得仍输出为硬编码零。

**失败处理：** 分开排查映射、Mfb、力对偶和端点速度；不平滑反力、删除首步或改变夹持集合解决不平衡。

### C6 建立充分积分无传递 CPU 时间步

**做什么：** 在新 stage2 模块实现固定参考完整质量 AVF 参照，复用旧 C 已验证数学结构但适配 657 自由分量、时变 lift、原 Ks 和流式材料作用。路径积分规则与材料体积积分规则独立编号；从三点 AVF 路径起步，以更高路径阶数在短窗复核。停止条件检查真实非线性残差，预条件只影响搜索；有限变形失稳时不得默认所有切线 SPD。保存路径功误差、非线性残差功、材料／稳定化／动能和边界分账。

**为什么：** 物理空间积分充分不保证 AVF 路径积分充分；共用旧小空间的稠密 K 和零稳定化账本会掩盖真实误差。

**产出：** 同空间 CPU 步进器、一步及短保持测试、`step-ledger.json`。

**如何验收：** 固定边界零外功保持、小振幅模态及前进／反演检查通过；物理状态不翻转且响应有限；真实残差达到预登记门槛，初始建议 atol=1e-11、rtol=1e-8，再按同单位尺度验证。建议每步账本闭合绝对误差≤1e-9 J，同时报告累计绝对误差；恒等式闭合与真实能量漂移分别列出，不以闭合误差代替精度。

**失败处理：** 首先分离路径积分、体积积分、线性／非线性求解和边界误差；不自动加阻尼、人工刚度或改变物理模型。

### C7 将物理时间步接入值事务

**做什么：** 在已有 `StateTransaction` 上增加 C 的物理验证与试探步包装；q、v、time、step、预测器、材料规则身份、账本、影响数值的缓存和子状态统一归属于试探。注入材料非法态、线搜索失败、边界失败、后置检查拒绝、过期 token、B 准备成功但物理步失败等事件。B/E 实际外部对象需要显式不可变提案适配，当前仅拥有值树不能代替外部原子性。

**为什么：** 第一阶段事务测试没有真实动力学，不足以保证一步失败后预测器或材料规则不会泄漏到下一步。

**产出：** 物理事务状态图、`transaction-step-audit.json`、最小 C/B 子状态协议。

**如何验收：** 成功一步只提交一次并严格前进时钟；任一故障使全部已提交物理状态和数值相关历史保持不变；重新尝试得到与干净初态相同结果。B/E 未接入时明确仅认证 C 和模拟子状态，不写“联合物理事务完成”。

**失败处理：** 将副作用前移为只读准备，接受后单点提交；缓存如不能原子撤销则限定为对数值无影响并用独立重算证明。

### C8 先评估真实吞吐和资源再启动长循环

**做什么：** 在实际 657 自由空间执行受限代表性试步，覆盖加载、保持、卸载和末保持，测真实材料调用、路径积分、线性求解、检查和输出开销；至少获得冷启动及多个接受步，不以零应变态一次调用外推全程。按观测最差迭代数和安全系数估计四档 48,000 步总墙钟、内存和轨迹磁盘。运行前冻结允许 CPU 小时、最大墙钟、峰值内存、数据盘余量和中断恢复策略；预算值按当前资源实测填写。

**为什么：** 首轮小空间不足十分钟的成本不适用于数百万材料点的共同空间，未经测算直接排 48,000 步可能不可执行。

**产出：** `throughput-preflight.json`、资源预约与准入结论、检查点格式。

**如何验收：** 外推包含完整算法而非 kernel；预算覆盖完整 1.6 s 和四档步数及恢复空间；同机计时注明竞争，正式性能另行独占。只有 C3—C7 通过且资源准入通过才启动 C10。检查点绑定源码、输入、dt、材料规则和最后已提交状态。

**失败处理：** 若预算不足，保留真实空间短窗结果，长循环标记 blocked_resource／not_run，给出实测预计成本。可研究数学等价缓存或请求后续资源安排；不能缩小空间、降低材料积分、缩短物理终点或把未完成步数写成完整验收。替代算法须另行验证后建立新协议。

### C9 执行短窗和末端误差归因

**做什么：** 四档 dt 分别通过短窗，单变量比较更紧残差、提高 AVF 路径阶数、提高材料积分阶数和不同模态分量；保持同一质量。加载初期、卸载末端和末保持各设窗口。需要“同一起点”诊断时，由一份已认证快照分叉各 dt；同时保留从初态连续推进的窗口，区分累计误差与局部误差。重新认证六阶在实际动态状态的充分性，不能只引用第一阶段两个静态状态。

**为什么：** 旧小模型终态 PK1 相邻差约 1.264%→1.258%，收缩很弱；可能来自近零分母、累计相位、边界、积分或求解误差，不能预设是时间阶数。

**产出：** `short-window-screen.json`、`endpoint-attribution.json`、相位／幅值／绝对误差图和充分积分复核。

**如何验收：** 每个变化只改变一个因素；输出未经滤波反力、全场和分区 PK1；对近零末态同时用冻结绝对尺度与相对值。至少能排除或定位主要误差源，不能以收紧容差一次无变化就宣称已证明时间收敛。

**失败处理：** 发现积分或求解主导时先冻结改进协议重做短窗；该轮失败仍保留。不能用自由振动的相位平移配准替代物理同时间比较。

### C10 完成四档真实空间完整循环

**做什么：** 在 C8 准入后，用共同空间、充分材料积分、同一初态和无传递 CPU 模型运行 dt=500、250、125、62.5 μs 至 1.6 s，对应 3,200、6,400、12,800、25,600 个接受步，共 48,000 步。所有相位断点准确落在时间网格上。保存每步原始反力和账本，完整 q/v 及可重建快照按预登记存储计划输出；在相同物理时刻和相同空间探针比较全场 PK1、纤维量和分区结果。

**为什么：** 短窗与小模型的成功不能证明真实目标空间完整加载—卸载—保持循环的可靠性。

**产出：** 四份原始轨迹、逐阶段比较、`cycles-summary.json` 和单独的时间认证状态。

**如何验收：** 四档均到达规定终点且步数完整；无非法 F、非有限状态或未记账失败。建议最细相邻档全过程、四阶段及终态原始反力／PK1 差≤2%，近零量沿用预登记的 1e-5 N 和 1e-4 Pa 绝对门槛并同时报告绝对值。连续档绝对差须给出收缩趋势；只满足最后两档门槛而收缩停滞时，只声明“有限档比较通过”，不得声明渐近收敛阶。空间精度仍单独标记未认证。

**失败处理：** 某档失败或资源中断按最后已提交检查点恢复，原失败记录保留；未恢复完成则四档验收未完成。近零阈值若需修改必须在新协议中重做比较，不能事后调宽原门槛。

### C11 交付 B 和 D 的固定动态接口

**做什么：** 向 D 提交时变 lift、完整质量、真实残差、切线作用、反力、能量账本及事务的固定语义和测试向量。向 B 提供已通过的充分积分快照、短窗及完整循环协议；B 材料候选只替换材料算子。用 C 私有适配器先验证接口，不等待公共合同代码；D 负责最终公共形式。提交独立重算脚本从 q/v 恢复 x/F/v/C、PK1、动量和账本。

**为什么：** 后续 GPU 或压缩必须在同一数学问题上比较，不能各自解释 q、力符号、路径积分或步接受条件。

**产出：** `dynamic-contract.json`、状态和方向测试向量、`handoff-package.json`、B 固定规则接入示例说明。

**如何验收：** 清洁来源下 CPU 独立重算一致；错空间、错质量、错误边界相位和旧 token 明确拒绝。B/D 尚未完成联合实现时仅认证 C 提供的接口和参考，不宣称动态 GPU 或压缩全循环通过。E 耦合接口可读取 C 的事务语义，但不阻塞本轮交付。

**失败处理：** 各组出现语义分歧先固定书面合同和最小反例，由各目录所有者修复；不修改父包函数或跨组抢改公共文件。

### C12 封存完整证据及剩余问题

**做什么：** 将新增源码、父包身份、动态初态、充分积分自检、完整质量秩、模态、约束、事务、短窗、循环及资源记录封存。区分“同空间 CPU 充分积分动力学”“时间有限档门槛”“渐近收敛”“空间连续体精度”“Eulerian/APIC”“GPU”“B/E 联合”各项状态。输出未完成原因及可继续的检查点。

**为什么：** 一项时间比较通过不代表空间准确，也不代表已经实现移动 MPM 或几何相关 APIC 惯性。

**产出：** `REPORT_ZH.md`、`acceptance.json`、源码／成果摘要、可复现读取与运行说明。

**如何验收：** 所有“通过”有实际空间、完整协议和原始数据支撑；加载能验证数据盘目标字节；父包及原 v22 摘要不变；重复载入同检查点得到一致后续状态。任何未运行的档位、材料族、后端或耦合明确标记未认证。

**失败处理：** 缺项不改变基线或下调目标，提交可复核阶段成果和剩余工作；后续另立新 run_id 补齐。

## 里程碑及资源并行

| 里程碑 | 核心产出 | 依赖与并行关系 |
| --- | --- | --- |
| C-M1 | C1—C5 正确初态、完整质量与约束 | 仅父冻结包；可与 A/B/D/E 同时开发 |
| C-M2 | C6—C9 真实步进、事务、吞吐与短窗 | 不等 B 压缩或 D GPU；需预约重型 CPU 资源 |
| C-M3 | C10 四档完整循环与终态归因 | C8 资源准入、C9 充分积分与短窗通过 |
| C-M4 | C11—C12 接口及证据封存 | C 独立参考可先交付；B/D 联合随后分批验收 |

A 的空间改善、B 的材料压缩、D 的静态 GPU 和 E 的孔弹性验证可以持续并行。大规模 A 参考和 C 完整循环应错峰占用内存及 CPU；正确性开发并行不代表正式成本测量可以互相竞争资源。

本轮通过后，下一批应分别比较“固定空间＋B 压缩”和“固定空间＋移动传递”，一次只增加一个变量；然后由 D 接入冻结动态算法。真正 Eulerian 网格力学、变几何 APIC 度量以及在线空间变化都需要独立推导与验收，不能由保存网格残余历史自动推出。
