## 写入边界与并行方式

未来 D 仅新增或修改 `engine/aniso_phase1/research_d/stage2/`、`benchmarks/research_d/stage2/`、`tests/research_d/stage2/`；结果使用 `docs/results/parallel-v22-stage2/D/<run_id>/`。D 独占新的公共 `engine/aniso_phase1/research_d/stage2/contracts.py` 和 `benchmarks/research_d/stage2/integration/`。A/B/C/E 只提供私有适配器与版本化交接包，不并发修改公共文件。

父包绑定的旧文件全部只读，包括旧 D 公共合同和各组第一轮文件。各组从源码快照建立独立副本，新增扩展文件记录独立哈希及上述父包哈希。旧加载器仍要完整通过；修改任何旧绑定源码都会被拒绝，不能更新旧清单、关闭源码校验或读取工作区未封存实现来规避。确需更改旧语义时另立迁移提案和新基线，本计划不授权静默迁移。

D1—D9 可在冻结输入上独立推进，无需等待 A 新空间、B 新压缩或 C 新时间积分。D2 同时接收各组字段需求，D10 在各组交接准备好后分批运行。E 的二维混合系统只共享交接规范和求解器能力声明，不强制映射到三维 A 的 657 个自由分量。

## 本轮验收口径

旧协议的阈值和旧结果保持原样。下列是第二阶段拟定门槛，实施时先写入新 `protocol.json` 并封存状态、方向、归一化尺度及随机种子；首轮正式求值后不能回调阈值。近零量采用 `abs_error <= atol + rtol * max(reference_norm, frozen_scale)`，不能用每个候选的结果选择分母。

| 检查 | 第二阶段门槛与解释 |
| --- | --- |
| 同状态 CPU/GPU | 能量、组装梯度、精确切线作用的归一化差均 ≤1e-7；分量绝对容差、能量/力/切线量纲尺度在 D2 预登记 |
| 导数独立核查 | 能量方向导数 ≤1e-4，梯度方向导数／切线 ≤1e-3；至少三个差分步长显示稳定区，不取偶然最优步长 |
| 伴随与对称性 | 位置/梯度映射伴随 ≤1e-10；精确保守切线双线性对称差 ≤1e-10，允许预登记绝对舍入项 |
| 材料充分性 | 复用父协议能量/力 rtol=1e-4、切线 rtol=1e-3 及原 atol/scale；只对父包两状态两方向有效，新增状态先重认证六阶与七阶 |
| 求解收敛 | 预登记真实缩放残差 1e-6 与 1e-8 两档，采用更紧档作最终等价判断；线性与非线性残差分别记录 |
| 同问题物理场 | 两后端均收敛后反力和共同探针应力归一化差 ≤0.5%；这只是后端等价门槛，不能替代 A 的空间精度门槛 |
| 性能晋级 | 至少 3 个独立进程、AB/BA 配对，完整成本中位收益 ≥10%，收益大于 A/A 噪声；其他主要控制场景不得出现 >3% 的可重复回退，否则限定采用范围 |

原父包的初态是右夹持已移动 0.005 m、速度为零的静态快照。D 可以据此求解同边界下的六阶材料静态再平衡；不得把归档 q0 自动当作六阶非线性势能的精确平衡，更不得自行规定动力学加载过程。

## 具体实施步骤

### D1 建立可复载的独立研究副本

**做什么：** 从父包源码快照恢复 D 独立目录，保留旧绑定文件；用父包原入口和指定哈希加载输入。检查数据盘链接的实际内容，既支持显式可信根，也测试解引用为真实文件的迁移副本。另记录运行环境、依赖锁、扩展源码身份和私有缓存目录。

**为什么：** 第一阶段已解决可信链接加载；本轮要验证实际研究副本仍遵循该保证，避免加载另一组实时修改的源码或仅复制 zip 后漏掉输入数据。

**产出：** `baseline-readonly-check.json`、`environment.json`、`extension-source-sha256.json`、迁移验证记录。源码 zip 是代码快照，不是全部历史实验数据备份，必需数组和报告须另核实。

**如何验收：** 原 589 项绑定源码及父包成果重验通过，迁移前后空间签名、输入字节和基准响应相同；越界链接、缺件、变更源码和错误父包哈希均拒绝。

**失败处理：** 停止依赖该副本的后续计算，恢复正确源码或输入；记录拒绝原因，不降低加载策略。

### D2 冻结字段和算子扩展合同

**做什么：** 在 D 独占的 stage2 合同中绑定自由 q `(219,3)`、完整 u `(369,3)`、xyz 最末维、q 的边界 lift、笛卡尔探针轴顺序和 dV。明确 `force` 为正势能梯度、机械内力取负号；材料积分需要显式 `order=6`，不能依赖 `CommonSpace.response` 默认的五阶。公布 A/B/C/E 能力声明和验证回调，预先封存本轮阈值与训练／验收状态集。

**为什么：** 各组字段看似相似，实际在全/自由坐标、位置/位移、加权/未加权伴随和力符号上不同；这些错误可能被小残差掩盖。

**产出：** 新合同 schema、字段与单位表、固定测试向量和 `protocol.json`。

**如何验收：** 用现有 CPU 映射完成 x=X+u、F=I+grad u、边界方向零 lift 和加权一次的往返与伴随检查；缺少空间签名、积分身份或能力声明的包不接受。A/B/C/E 私有适配器可由各组独立实现，不等待 D 的优化内核。

**失败处理：** 拒绝不一致交接，修私有适配器或新增合同版本；不改变旧字段含义。

### D3 建立共同空间 CPU 静态参照

**做什么：** 对归档状态、父包固定扰动及预登记新增有效有限变形状态，直接调用原势能／材料实现得到 U、完整及自由梯度、精确切线作用和约束反力。新增状态先比较六阶和七阶积分。记录原 Ks 与材料贡献，构建小批独立差分方向及混合载体—局部方向。

**为什么：** CUDA 对照必须对应实际共同空间和当前材料；旧张量问题、旧线性 q0 或未经充分性认证的新变形不能直接作为参考。

**产出：** CPU 参照 NPZ、状态与方向哈希、材料充分性补充报告及导数检查。

**如何验收：** 父包原检查保持通过；新增状态的积分及导数达到事前门槛；出现 detF≤0 时按协议拒绝而非截断；657 个自由分量的真实算子必须被覆盖。

**失败处理：** 区分材料积分不足、导数错误、状态非法和资源不足；提高参照积分时另立规则身份并通知 B/C，不混入原六阶已认证集合。

### D4 将实际基函数映射与其伴随搬到 GPU

**做什么：** 在 D 新目录实现 float64 Warp 载体延拓、稀疏原始局部基、局部基变换及反向伴随；分片生成积分点位置和梯度。显式处理自由到完整位移插入、约束方向为零和完整反力返回，缓存键绑定空间/边界/规则/设备 context。

**为什么：** 共同空间包含载体和非正交局部函数；只移植规则网格张量核无法得到同一离散空间。

**产出：** 新 GPU 空间适配器、映射逐层差异报告和内存估算。

**如何验收：** q0、混合随机方向、局部方向与刚性约束探针逐层对照 CPU；通过完整位置/梯度伴随及接口形状检查。真实 144 函数空间必须通过，缩小样例只作诊断。

**失败处理：** 在最早出现差异的层定位顺序、转置、权重或边界问题；禁止用重排后未绑定的向量掩盖差异。

### D5 验证 GPU 原势能和精确材料切线

**做什么：** 在 D4 真实积分布局上实现/复用原 Hencky 与纤维法则，分别归约 U、梯度及精确 Hessian-vector 作用，加入原 Ks。测试重复奇异值、近旋转、压缩和非均匀 F；所有比较使用同一阶次和同一状态。将求解用的曲率修改算子与精确物理切线分别命名并保存。

**为什么：** 预条件或曲率保护可以帮助求解，但不能替代原势能的导数，也不能用平均材料或常切线冒充有限变形等价。

**产出：** 材料 GPU 算子、能量/梯度/切线 CPU-GPU 对照和差分报告。

**如何验收：** 达到本轮算子、导数与对称性门槛；反力保留固定分量；异常与非法 detF 拒绝。压力混合块不进入本固体算子认证。

**失败处理：** 保留原始状态和最小反例；只在明确状态范围内认证，通过范围不能由删除不利样例扩大。

### D6 确认曲率合法性与求解策略

**做什么：** 对预登记状态检查对称性、约束后刚度谱或可靠方向曲率，区分真实负曲率、近零模态和数值误差。只有验证 SPD 的子问题使用 PCG；其他情况使用适当的对称不定或一般求解策略，并以原能量线搜索／信赖域和真实残差控制。任何正则或曲率投影单列为迭代辅助。

**为什么：** Hencky 在压缩下并不保证全局凸；657 自由分量的局部空间条件数也不能由旧张量问题推断。

**产出：** 曲率地图、求解器适用性声明及故障回退表。

**如何验收：** 构造负曲率和近奇异控制，证明不会无条件启动 PCG或虚报收敛；原势能、物理梯度和最终平衡方程保持一致。E 的混合系统只能通过独立能力合同进入其他求解器。

**失败处理：** 保留 CPU 可复核求解，记录失败类型；不得向物理势能或质量偷偷加对角稳定项。

### D7 研究预条件与实际总成本

**做什么：** 比较无预条件、尺度/块对角、载体—局部块、重叠局部块等有限候选；保留载体—局部相互作用的真实方程。记录构造、因子、上传、迭代、同步与回退成本；分析高条件数是否来自基、材料还是边界。

**为什么：** 迭代数下降可能被小问题的构造和设备开销抵消；旧 D 大问题的 12.61× 不能外推到本空间。

**产出：** 固定候选清单、预条件谱/迭代/完整成本对照、内存上限与复用条件。

**如何验收：** 每个候选解同一方程并满足同一真实残差；预条件不改变反力或材料积分。基于完整成本选择范围，不能仅以迭代数排名。

**失败处理：** 没有稳定收益时保留 CPU 或简单预条件，把复杂候选记为诊断结果。

### D8 完成真实共同空间静态平衡

**做什么：** 从 q0 在固定 0.005 m 边界下进行原势能的 CPU/GPU 独立再平衡；新增幅值或材料只作为另立输入身份的泛化控制。比较自由梯度、完整反力、共同探针 PK1、原势能、Newton/线搜索轨迹和失败回滚。

**为什么：** 同一状态上的算子一致并不能保证完整求解一致；q0 的归档来源也不自动保证新材料阶次下已平衡。

**产出：** 原始平衡轨迹、终态场、真实残差与 CPU/GPU 静态验收报告。

**如何验收：** 两档残差均记录，最终等价按紧档判断；物理字段满足本轮门槛；无插值排序伪差、无平滑。A 的连续体空间精度仍单列“未认证/未通过”。

**失败处理：** 区分迭代未收敛、多个平衡分支和后端错误；若分支不同，使用共同初值与延续路径重审而非只比最终能量。

### D9 测量内存与可复现性能

**做什么：** 在正确性冻结后进行冷/暖两类 AB/BA 配对测量；计入基构造、CPU 批处理、JIT、设备上传/读回、同步、求解及输出评估。首次编译单列并同时报告包含首次编译的总成本。记录峰值主存/显存、有效吞吐、GPU UUID、同机负载和 A/A 噪声。

**为什么：** 本空间较小，可能出现核更快但总求解更慢；异步 GPU 计时也容易漏掉同步成本。

**产出：** 三独立进程以上的全轮数据、配对分布、内存和传输分项及适用范围。

**如何验收：** 按预登记同误差/同残差规则比较，符合10%收益和噪声条件才推荐性能晋级；主要场景 >3% 可重复回退必须限定采用范围。正式计时独占 GPU，与 A 大参考错峰。

**失败处理：** 无加速仍可交付正确算子；不得通过降低精度、放松残差或移除反力/应力计算制造加速。

### D10 分批接收 B C E 扩展接口

**做什么：** 先接 B 固定材料规则，在同一空间、相同质量身份下做 CPU 算子比对；C 提供方程、惯性、边界功和事务签名后接其只读状态/静态算子接口；E 提供独立二维 mixed block 与真实残差，验证一般混合系统能力声明。新增综合入口均位于 D 独占 integration 目录。

**为什么：** 可以提前完成公共接口，但不能在 C 时间方程未冻结前承诺动态 GPU，或把 E 混合系统伪装成固体 SPD。

**产出：** A/B/C/E 接口兼容矩阵、拒绝用例、每项有明确前置条件的集成清单。

**如何验收：** 相同签名的字段、方向、残差和事务按约定复载；错误质量规则、过期状态、缺少物理能力或混合系统误报 SPD 均被拒绝。动态 GPU 本轮仅保留接口待办，不列已验收成果。

**失败处理：** 某组尚未交付时记录该项未运行，不阻塞 D1—D9；不以模拟接口返回值替代真实交接验收。

### D11 封存交付与独立复载

**做什么：** 封存新增源码、协议、依赖、原始数据、拒绝记录、性能记录和报告，绑定父包及空间哈希。使用另一独立副本检查父包和扩展包闭包，明确静态/GPU/动态/连续体各项能力状态。

**为什么：** 新结果必须可追溯到实际执行代码，并使其他组读取固定交付而非正在变动的工作目录。

**产出：** 新扩展包、成果清单、独立复载记录、简洁采用/不采用决定；旧文件和父包前后哈希核查。

**如何验收：** 所有绑定文件匹配，独立复载和指定控制通过，失败记录未被删除；明确认证的是固定共同空间上的静态后端，未切换生产默认，未宣称空间精度或动态 GPU 通过。

**失败处理：** 缺证据时保留研究结果并列出未交付项，不能把计划完成等同数值验收通过。

## 阶段依赖和交付节奏

第一批交付 D1—D3 的身份、接口和 CPU 参照，供 B/C 并行使用；第二批完成 D4—D8 的 GPU 正确性与真实静态求解；第三批交付 D9 性能和 D11 封存。D10 根据各组版本逐项接收，任何后续 A 新空间均建立独立扩展，不覆盖本轮输入。未来动态 GPU 需要另一阶段计划及 C 的真实共同空间完整循环证据。
