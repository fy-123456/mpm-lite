## 数据和算子交接合同

公共接口先锁定语义，再由 D 提供统一封装。每个交接包包含 `schema_version=1`、基线源码散列、生产者及代码散列、输入散列、单位、dtype、device、坐标系、材料参数、边界条件、物理/参考体积约定和随机种子。增加字段必须保持旧字段语义；破坏性变更升级 schema，并由 D 提供显式适配，不能让其他组自动读取最新未验收输出。

| 合同对象 | 必须包含的语义 | 所有权 |
| --- | --- | --- |
| 空间映射 | 自由度排列、基函数/基变换、约束提升、物理和人工边界；位置与 F 的评估、方向导数和力的伴随映射 | A 定义空间；C 增加动态状态使用规则 |
| 材料积分 | 点位置、正参考体积、方向/结构张量、参考变形和材料历史；同一规则的能量、PK1、切线作用；规则冻结编号与误差指标 | B 定义压缩表示；材料法则本身默认不改 |
| 材料法则 | 能量密度、应力、切线作用、内部变量及提交规则；参数和有效域 | 既有法则作基线；E 的新物理在独立命名空间提供 |
| 动态状态 | 载体和局部自由度的坐标、速度、APIC 状态、材料历史；质量及交叉质量作用、约束和冲量；试探/接受/回滚事务 | C 唯一负责运动学推进和总事务顺序 |
| 求解器 | 给定状态的残差、精确切线作用、预条件器、约束投影、真实残差停止条件、失败原因 | D 负责算法实现，不改变物理势能或边界条件 |
| 耦合数据 | 相速度、相质量/体积、压力、阻力张量、相互作用力和耗散；饱和度等字段只在启用对应模型时出现 | E 定义；通过 C 的外力/状态接口接入 |

交接前必须明确 q 表示总位置还是位移增量。推荐公共位移约定为 `x=X+u(q)`，`F=I+∇u`；旧实现若直接对总位置求梯度，应由适配器转换并验证，不能额外加一次或少加一次单位阵。非线性映射的切线包含映射自身的导数，不能机械套用固定线性基的公式。

B 负责压缩样本及其材料内部状态，C 负责几何/F 历史的跨空间迁移及整步提交顺序；E 负责新增物理内部变量。Newton/线搜索内禁止改变采样分组、局部基或已提交历史。接受时间步后才能按明确规则更新，失败必须完整回滚。重分组、基底迁移和时间积分的能量变化分别记账。

C 不能把 v22 的新增 α 无条件塞入原方形载体映射，也不能套用 v20 的材料不可见自由度消元。新增 α 通常具有真实变形和惯性，必须包含其速度、历史、`M_yα` 与 `M_αα`。只有经过独立证明的不可见/零惯性方向才能按声明的模型约束处理。

## 统一验收层次

以下是未来任务的预先约定；未执行前不标记通过。具体任务允许更严阈值，但必须在看结果前写入协议。

1. **实现一致性。** 检查单位、dtype、形状、有限值、体积/质量、方向归一化、边界分类和历史事务。CPU float64 小问题的能量方向导数相对差建议不高于 `1e-6`，切线方向检查不高于 `1e-5`，对称性不高于 `1e-10`；扫描多个扰动尺度并保存完整误差曲线。分母接近零时同时使用预先声明的绝对量和尺度，不能事后挑有利归一化。
2. **代数求解。** 记录真实残差、约束残差、迭代次数、负曲率和回退，不以递推残差代替真实残差。参考解继续检查功恒等式；求解容差至少做两档敏感性对照，使求解误差不会主导所报告的物理差异。GPU 或精度改变需另作等价验收，不能只复用 CPU 通过标记。
3. **积分与压缩。** 同一个物理状态、空间和材料法则下对照完整积分，分别记录能量、组装内力、应力弱形式矩和切线差；若提供压缩应力重建，另验共同物理探针 PK1。在同一 F 上重新求同一本构 PK1 不能用作积分压缩精度证据。B 的快照建议预算为能量/组装内力/应力矩及已有重建应力各 1%、切线作用 2%，完整循环中的压缩增量误差建议不高于 1%；这些是分项预算，不保证组合后自动达到空间 2%。
4. **空间。** 延续 v22 的目标：反力 1%，全域/夹持/内部及声明的深内部应力与纤维应变 2%。参考按 h/p 分别认证；现有内部认证不能替代全区认证。完整场、绝对 RMS、反力和自由度/成本同时报告。最终参考不得参与基函数构造、选点或挑选最优轮次。
5. **时间与迁移。** 相同输出时刻比较至少四档 dt 的完整加载、保持、卸载、末端保持；建议全循环和各阶段的原始反力、全过程及阶段末应力均不高于 2%，同时检查最细连续档差异收缩。至少报告终态、迁移瞬间和能量分项，不删首步、不平滑反力。若指标近零，改用预先声明的绝对尺度一起判定；不能只因相邻差小就宣称渐近阶已建立。
6. **物理与性能。** E 单独检查相质量守恒、作用反作用和耗散符号。D 分别报告固定算子的实现加速和达到同一物理误差的端到端成本，计入预处理、压缩、基底生成、迁移、传递、求解和同步。相同自由度不等于相同成本。

新的测试如果揭示旧归档问题，应保存反例和影响范围，不覆盖旧报告。物理目标未达标时允许交付阶段结论，但状态必须写“未通过”，不靠改变物理参数、删除困难区域、提高耗散或放宽容差获得通过。

## 计算资源和结果隔离

开发、静态审查和小型测试可以并行；公平性能测量应独占目标 GPU 或约定的 CPU 核。每个运行记录 GPU UUID、设备型号、驱动/库版本、线程数、内存上限、缓存状态和同机负载。其他组在计时窗口内暂停对同一设备的竞争，受干扰的计时不参与正式比较。

每组使用独立 Warp 缓存、临时目录、端口和输出目录，路径放在自己的工作副本或结果前缀下。不得同时编辑一个缓存配置或使用同一固定 Viser 端口。先估算内存和磁盘，再运行大参考；触发资源限额后缩小试验或调整实现，不删除其他组文件或擅自终止其进程。

`run_id` 建议由 UTC 时间、任务、实验编号组成。每次输出保存输入协议、源码散列、设备精度、原始数值、验收状态、失败原因和续算来源。结果目录只追加，完成后封存。各组的科学开发并行，不要求五个大规模计算作业同时争用硬件。

## 集成顺序和交付要求

各方向先提交独立结果，再由 D 组织短期集成窗口，其他方向只提供自己的适配器与修复。

| 组合阶段 | 固定项与变动项 | 验收目的 |
| --- | --- | --- |
| A × B | 原/新空间分别配完整/压缩积分，四组对照 | 区分空间收益、压缩误差及二者相互作用 |
| A × C | 先用完整积分接固定新增空间，再启用空间变化 | 区分惯性扩展与迁移误差 |
| B × C | 固定空间，对比完整与压缩历史循环，再启用重分组 | 分开积分误差与历史迁移能量 |
| A × B × C | 对已通过单项和两两测试的版本联合验收 | 重新检查整体精度，不叠加单项通过结论 |
| D 后端替换 | 冻结上述数学问题，比较 CPU 与 GPU | 确认实现等价和完整性能收益 |
| E 耦合接入 | 先接既有固体基线，再逐项替换 A/B/C/D | 分离新增物理与数值优化的贡献 |

每项交付至少包含：版本及输入指纹、独立入口、配置说明、新增/修改文件清单、原始结果、自动验收摘要、失败与限制、资源及成本报告、与公共合同的兼容性说明。集成时重新核查基线；如果其他工作已产生 v23 或新的未归档源码，应报告差异并显式更新计划基线，不能悄悄切换。

本次文档交付只验证引用、基线散列、步骤完整性与修改边界。五个研究方向的算法验收、CPU/GPU 测试与性能结论均待后续实施。
