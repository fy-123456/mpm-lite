本计划以已完成并封存的本地 v22 为基线，供后续实施使用。本次只编写计划，没有修改求解器、运行新实验、安装依赖或切换默认。共同身份、并行规则和接口语义以 [00 基线与并行合同](00_BASELINE_AND_PARALLEL_CONTRACT_ZH.md) 为准；本地没有 Git 元数据，不编造提交号。

基线源码包 SHA256 为 `136529c866133aac10af77126c839f12a2769073ee5ec964f46dcadeca7adee4`，本次共同核验范围为 488 个源码条目、131 个成果条目。v22 的实现与实验已完成，但全域空间应力和参考自检仍未通过，且该轮没有 CUDA 验收。详见 [v22 完成清单](../results/lite-aniso-mainline/v22/completion-check.json) 和 [最新报告](../ANISO_LITE_GRIP_HIGH_ORDER_ZH.md)。

## 目标与现有能力

目标是在相同物理问题、空间表示和误差要求下，降低线性／非线性求解、局部空间构造和完整时间步的成本，并给出可复核的 GPU 与 CPU 一致性证据。更快地求解一个空间精度不足的离散问题，不等于解决空间误差。

已有实现必须继承，不能重新算作本方向的新增贡献：

| --- | --- | --- |
| 高阶矩阵自由张量算子、可分离预条件与 CG | [tensor_reference.py](../../engine/aniso_phase1/tensor_reference.py) | 适用性、成本和异构材料扩展；GPU 实现对照 |

## 所有权与并行依赖

后续拟新增的 D 私有目录为 `engine/aniso_phase1/research_d/`、`benchmarks/research_d/`、`tests/research_d/`；结果放在 `docs/results/parallel-v22/D/<run_id>/`。这些是计划路径，本次没有创建实现或实验结果。

D 唯一负责拟新增公共模块 `engine/aniso_phase1/research_contracts.py` 以及集成入口 `benchmarks/research_d/integration/`。D 只负责封装和适配，不重新定义 A 的空间、B 的压缩、C 的推进与总事务顺序或 E 的物理模型。其他方向不等待公共模块落地：依据 00 的语义合同，先在各自目录以私有 adapter 和现有冻结输入开展研究，D 最终适配。并行阶段所有方向均只读旧源码和 v22 归档；旧 `__init__`、types、solver 等共享核心文件，只能由 D 在单独集成阶段按已审定接口修改。

A 的参考认证与局部空间、B 的材料压缩、C 的动态一致性和 E 的耦合物理可与 D 的独立算子研究并行。D 不替其他方向宣布精度通过。开发并行，GPU 性能评测串行；同一张 GPU 不同时运行多个方向的正式计时任务。

## 分步实施

### D1 冻结算子与问题身份

**做什么：**为静态张量问题、局部校正和既有隐式快照分别记录几何、空间基、边界、材料切线、精度、自由度、状态哈希及容差；先选小型独立组装可承受的问题

**为什么：**GPU、预条件与空间变更容易混在一起，必须先固定比较对象

**产出：**私有 adapter、问题清单、只读输入引用；不复制成另一套未标识基线

**如何验收：**CPU 原算子和独立组装算子作用一致，边界行及自由度映射一致；每个记录可追溯到冻结输入

**失败处理：**身份或输入不一致即停止该组比较；保留失败记录，不调整物理参数补救

### D2 建立数学与物理验收口径

**做什么：**核对 `Kx`、对称性、能量方向导数、去质量静态模式、约束消元及反力；区分真实 Hessian、用于搜索的正定近似和预条件器

**为什么：**SPD 预条件器不能证明真实 Hessian 始终 SPD；残差下降也不能替代空间精度

**产出：**独立小矩阵 oracle、尺度化误差定义、异常分类

**如何验收：**float64 小问题算子相对差建议 ≤1e-9、对称性 ≤1e-10；势能／力／切线用步长扫描且满足 00 门槛；阈值在实施前写入协议

**失败处理：**排查边界、积分、基变换和精度；不能加入未声明对角刚度或删除零模态过关

### D3 测量现有性能组成

**做什么：**固定同一冻结问题，分开统计张量作用、预条件构造／应用、归约、局部校正、正交化、主机设备传输和同步；运行计时与详细 profiler 分离

**为什么：**已有可分离预条件未必是瓶颈；局部空间同函数数不等于同成本

**产出：**基线时间分解、峰值显存／主机内存、迭代与残差轨迹

**如何验收：**先完成同版本 A/A 稳定性测量；未预热计时、编译时间和稳态时间分列；完整范围与子阶段口径相容

**失败处理：**若噪声与候选收益同量级，标记无结论，调整测量窗口而不是报告最佳一次

### D4 预条件组合研究

**做什么：**保留可分离预条件作为控制组；研究局部块／重叠 Schwarz 与粗空间组合、材料方向感知的尺度化；针对变化切线定义重建和复用条件

**为什么：**v22 较大支撑校正更昂贵；异构材料可能削弱常系数可分离近似

**产出：**每种候选的构造成本、应用成本、迭代和总耗时；明确支持的材料／边界范围

**如何验收：**在相同真实残差停止条件下比较；PCG 使用固定 SPD 预条件，变化或非对称预条件改用合适 Krylov 方法并独立验证

**失败处理：**预条件不定、复用失效或迭代变坏时回到已验证控制组；不把预条件项加进物理势能

### D5 GPU 算子与局部批处理

**做什么：**优先移植张量轴运算、材料切线作用、局部残差和批量校正；先保留 float64，逐项对照 CPU；为大支撑限制批次和临时数组峰值

**为什么：**减少传输与重复 launch，比直接整体重写更容易定位差异

**产出：**D 私有 Warp 模块、CPU／GPU 同输入结果、内存与批处理策略

**如何验收：**每个算子先过 D2；GPU 状态无 NaN/Inf，边界不泄漏；针对最大测试配置记录峰值显存，不因超限截掉物理区域

**失败处理：**降低批量或按区域分块；尚不支持的算子显式留在 CPU 并计入传输成本，不能隐藏回退

### D6 CPU／GPU 非线性与失败一致性

**做什么：**复核原势能、精确残差、切线作用、曲率失败、线搜索、历史提交／回滚；包含压缩、重复奇异值、硬夹持和多种方向

**为什么：**算子近似一致并不保证迭代路径、反力与历史一致

**产出：**同状态迭代记录、失败注入和回滚测试、诊断字段对照

**如何验收：**同一离散问题最终反力／应力差建议 ≤0.1%，真实残差满足原协议；离散导数和回滚另设严格门槛；物理空间 2% 门槛不被替代

**失败处理：**冻结首个分歧状态定位；允许不同迭代路径但不允许跳过物理约束；无法说明时保留 CPU 默认

### D7 设备常驻与缓存生命周期

**做什么：**在通过的 GPU 路径上减少逐迭代主机读回；缓存局部拓扑、轴算子和工作区；仅在输入、边界、空间基与资源身份均一致时复用；再评估 Graph

**为什么：**现有 Q1 resident 仍有 `.numpy()` 读回；动态基和活跃网格会使缓存失效

**产出：**缓存依赖表、失效测试、同步次数与传输字节对照

**如何验收：**同尺寸不同拓扑、基变化、材料变化、实例切换、释放重建均不得误命中；冷启动与暖复用成本分开报告

**失败处理：**缓存证据不足就保守重建；Graph 捕获失败退回原 launch，记录回退而非绕过检查

### D8 异构与规模扩展

**做什么：**在已冻结控制组外，增加网格规模、局部支撑大小、纤维角度、刚度比、材料分布；分别固定粒子数和活动积分规模

**为什么：**证明改进不是只适合 F45 盒体或某一显存规模，并检验 Lite 求解成本是否重新依赖 PPC

**产出：**规模—时间—内存曲线、预条件稳健性区间、适用边界

**如何验收：**同精度／同残差口径；无人工减少积分点、粒子或迭代门槛；报告失效配置；以同误差达成成本为主要指标

**失败处理：**超大配置只记 OOM／资源上限，不能改小场景后仍沿用原场景名称；不稳健候选限定适用范围

### D9 正式公平性能判定

**做什么：**独占同 GPU 做交替 A/B、B/A，固定场景与误差；至少三组独立进程配对，预热单列；静态问题统计每次完整求解，动态问题另计完整物理步

**为什么：**v22 耗时受并发争用影响，不能作为公平加速数字；减少迭代可能被预处理成本抵消

**产出：**逐次记录、均值／中位数／P95、总预处理与复用摊销成本、失败率

**如何验收：**建议总耗时中位数改善 ≥10% 才作为默认优化候选，任一主要控制场景的总耗时中位数回退超过 3% 时，必须解释或限制启用范围；这是拟定门槛，不是已有结果

**失败处理：**无稳定收益即保留为诊断或可选路径；不选取最有利轮次，不把 CUDA 核时间当完整步时间

### D10 公共接口适配与最终集成

**做什么：**在独立方向提交验收产物后实现公共合同模块，逐个适配参考场、空间基、状态、算子、边界和统计；先接只读静态比较，再接已通过 C 动态门槛的空间，最后接 E 的已验证物理

**为什么：**并行阶段自由探索与最终单一状态语义需要隔离；v22 空间不能直接冒充已验证移动算法

**产出：**公共接口、集成驱动、版本与能力矩阵、逐项开关和回退点

**如何验收：**每次只接一个方向，重复其关键验收；失败必须可归属具体接口；新空间未过动态门槛时只能静态集成

**失败处理：**拒绝不完整接口或未声明状态；回退该项并继续不依赖它的集成，不改写旧归档

### D11 组合验收与交付

**做什么：**对最终组合完成静态、动态、设备一致性和代表场景回归；保存源码清单、硬件软件、输入输出、测试／性能原始记录

**为什么：**单项通过不等于组合通过，用户需要可复核的收益和局限

**产出：**独立输出目录、成果哈希、采用／拒绝／暂缓清单、生产接入说明

**如何验收：**原物理门槛保持；默认切换需满足共同合同，未通过的方向继续可选；完整测试与局部测试分别声明

**失败处理：**组合回退优先于降精度、放松残差或删去难例；未完成 GPU／全仓覆盖必须写明


## 数值阈值与性能口径

本节步骤中的 `1e-9`、`0.1%`、`10%`、`3%` 是后续建议门槛，不代表已有实验已达到。实际实验协议需在运行前固定尺度、绝对容差及比较区域。对于近零反力／应力，采用单位明确的绝对误差和固定基准尺度，不能靠很小分母制造百分比，也不能任意增大分母掩盖差异。

GPU 与 CPU 同算子差异、离散解相邻网格差和连续体误差是三类结论。v22 参考最终同网格 Q3/Q4 全域应力差约 2.195%、夹持区约 3.251%，因此即便 GPU 完全复现 CPU，也不能宣布全域 2% 空间门槛通过。新的参考认证由 A 提供；A 的同预算局部空间成本需把局部求解及正交化计入，B 的压缩成本需计入分组、重建与规则验证。

`engine/types.py` 当前启用 float64，既有 Warp 依赖也已存在。后续若研究混合精度，单独冻结 float64 控制组、真实残差重算方式、失效回退和精度适用范围；不通过把所有物理数组改为 FP32 来完成本计划。新的压力约束或非对称耦合算子不能直接沿用仅对 SPD 适用的 PCG 验收。

## 独立研究与最终成果的区分

D1–D9 可以对既有冻结输入独立执行，不依赖 A/B/C/E 全部完成。它们能证明指定离散算子的正确性和成本。D10–D11 才能对组合算法作结论；若某方向尚未通过，交付中保留该状态，不能把多个分支最好的数字拼成一个不存在的完整算法。

最终报告必须回答：加速了哪个算子或哪段完整流程、固定了哪些物理与误差要求、预处理是否摊销、用了多少内存、有哪些回退或未覆盖配置。新测试命令由后续实际文件生成，不在本次计划中提供尚不存在的可执行命令。
