## 3. 共同验收口径

### 3.1 工程误差与实际稳定性分别检查

共同物理位置、同一时刻或同一时间区间上，采用：

\[
e_y=\|y-y_{ref}\|_W,\quad B_y=a_y+0.05\|y_{ref}\|_W,\quad \eta_y=e_y/B_y.
\]

`W`沿用共同物理探针的归一化区域权重；整体、夹持区、过渡区和内部区分别报告。`η≤1`通过。数值为4.52表示超出预算4.52倍，不是4.52%误差。

| 量 | 绝对项a | 对齐要求 |
| --- | --- | --- |
| 位移 | 5e-5m | 去掉显示倍率，比较真实物理位移 |
| 速度 | 1e-4m/s | 同一物理位置，禁止比较不同空间裸系数 |
| PK1、纤维应力、Cauchy应力 | 0.02Pa | 骨架／总应力及各定义分开 |
| 完整反力 | 1e-4N | 同一时间区间平均，保留惯性、稳定化和压力贡献 |
| 压力 | 1e-3Pa | 单元体积加权，跨网格先保守限制 |
| 定向面流量、边界净流量 | 1e-10m³/s | 同一物理面、同一区间 |
| 流体含量、累计排水／源项 | 1e-10m³ | 广延量求和，不能按压力方式平均 |

压力与反力的时间比较不得用插值峰值替代原始区间数据：

\[
\bar R_{[a,b]}=\frac{1}{b-a}\sum_jR_j\Delta t_j,
\qquad Q_{out}(T)=\sum_j\dot Q_{out,j}\Delta t_j.
\]

性能实现同输入的算子等价继续使用已验证的分量量纲及 `rtol=2e-5` 等原门槛；不要求逐位相等，不把位移、压力、流量混为一个无量纲最大差值。

### 3.2 保留物理方程、提交语义和完整材料／质量

研究耦合保持：

\[
r_m=\alpha\Delta V+C\Delta p+\Delta t Bz-\Delta t s,
\qquad Hz-B^T\bar p+g_b=0,
\]
\[
\Delta V=\bar G\Delta q,
\qquad W_{p,s}+W_{p,f}=-\alpha\bar p^T\bar G\Delta q+\alpha\bar p^T\Delta V=0.
\]

- 物理量有限、`min(detF)>0.1`、原真实残差和边界约束通过；不能用额外阻尼、压力裁剪、人工质量或稳定化系数调整掩盖异常。
- 完整质量M7及材料q7用于新研究轨迹；不能把已有固体q5证书扩展到新空间、步长或耦合。
- 逐步核查质量、压力功和非负Darcy耗散；独立核查累计能量 `ΔE+∑Δt zᵀHz−∑W≈0`。沿用原1%能量预算和绝对项，不仅看人为拆分后的账面闭合。
- 混合系统使用当前一般LU与原系统残差。某子块正定不代表整体系统可直接用CG。
- 失败恢复必须包含q、速度、预测器、压力、流量、历史和累计账目；失败步不发布新generation。
- 每项结论限定窗口、区域、网格和参数。固定骨架精确时间参考不等于可变形耦合真解；短前缀通过不把旧完整短窗改写为通过。

**为什么：** 已有五点结果证明差异持续存在，但尚未区分初始投影与随后轨迹偏离。

**如何验收：** `S1/state-map.json`时间严格对应，空间身份独立，物理探针与权重相同。原分解重组误差通过已用门槛；不同空间不直接减系数，不将分量范数相加为总误差。

### S1.2 做“同刻投影／实际演化”的零步分解

**做什么：** 对每个正式状态，用已有受约束完整质量投影产生该时刻的候选表示 `Π_M q_f(t)`；这只是诊断状态，不作为候选历史的新检查点。计算候选实际状态和投影状态的恢复加速度，均映射到共同物理探针：

\[
\Delta a(t)=
\underbrace{a_c(q_c(t))-a_c(\Pi_Mq_f(t))}_{\text{候选轨迹相对同刻投影的偏离}}
+\underbrace{a_c(\Pi_Mq_f(t))-a_f(q_f(t))}_{\text{同刻空间表示差异}}.
\]

材料、稳定化与边界交叉质量分别分解；保留 `M_ff^{-1}` 和 `−M_fb a_b`。诊断模型顺序构造，投影与能量计算不修改原存档。

**为什么：** 实际轨迹间的差异同时包含表示误差和历史偏离，不能全部归咎于基函数，也不能全部归咎于步长。

**如何验收：** `S1/projection-vs-history.json`向量重组通过；受约束质量投影正规方程与既有检查一致；各区域分别报告。把这称为诊断拆分，不能称为完全隔离了非线性因果效应。

### S1.3 检查稳定化的坐标变换与输出敏感方向

**做什么：** 对照当前 `gpu_operator.py`／profiling路径实际公式。稳定化作用于原载体坐标：

\[
y=y_{ref}+\ell_s(t)+A_sq_f,\quad U_s=\tfrac12\operatorname{tr}(y^TK_sy),
\quad f_s=A_s^TK_sy,\quad K_{s,r}=A_s^TK_sA_s.
\]

这里A_s是自由未知量到原载体的组合映射，ℓ_s(t)包含规定边界的提升；使用完整坐标时则由完整q显式承载相同边界。显式核查载体提取、完整／自由自由度、边界提升、变换及交叉块。复用已通过的初态物理梯度归一化差分证据；只有发现新异常或修改导数时，才对最多2个相关方向、两个扰动尺度补验。

从五点已有诊断中选择最多8个输出相关方向，报告质量归一化恢复力、稳定化曲率与物理速度／反力敏感性。不同空间按物理子空间或重叠匹配，不能用相同模态编号当作相同运动；静止切线模态只是解释工具。

**为什么：** 位移小不代表速度或加速度小：`u=A sin(ωt)`对应速度幅值`Aω`、加速度幅值`Aω²`。必须判断高恢复力是否真正影响所关注输出。

**如何验收：** `S1/stabilization-chain.json`和`S1/output-sensitive-directions.json`解释差异发生在哪个变换／区域／方向；未发现公式问题就保留原公式。发现明确装配或索引错误可在新分支修复，并使旧错误轨迹失去当前数值资格，按预算重验；不得悄悄调系数。

### S1.4 给出后续单一决定

**做什么：** 汇总为“已定位实现错误”“空间表示／投影主导”“历史与时间响应主导”或“仍未充分定位”，附证据和不确定性。为S3登记一个短前缀；为S4登记可使用的静态工况和初态方向，晚期未分辨轨迹只作诊断。

**为什么：** 无明确判断就继续增加步数或训练空间，很容易把几种误差一起改变。

**如何验收：** `S1/diagnosis-decision.json`写明哪些源代码可以改、哪些方程保持、哪些分支不触发。疑难高风险项停止其分支，保留最小复现；普通可定位问题自行修复后继续。S2独立推进。

## 6. S2：先用小矩阵选择边界薄层，再运行实际耦合

### S2.1 分方向核查边界通量与物理参数

**做什么：** 冻结OBS原参数：`alpha=0.8`、`storage=0.0002`、`pressure0=0.2Pa`、`reservoir=0.002Pa`、源项0、`mobility=1e-7×原MOBILITY完整张量`，原几何、零夹持、M7/q7、当前H均保持。窗口先固定`[0,2e-4]s`，既有16/32单元结果是基线。

按所有实际排水面及x/y/z方向分别统计瞬时区间流量和累计量，核查符号和抵消；不能只看一个标量净流量。复用固定骨架诊断，量化首层厚度、压力跳变及作用方向。

**为什么：** 原关系 `j=−K∇p` 对边界梯度敏感。上一轮首步差异被固定骨架复现约99.997%，支持薄层问题，但不能假定只有x方向边界重要。

**如何验收：** `S2/boundary-attribution.json`分面量与全局质量账目一致，旧网格误差可复现，压力初值／边界／张量未变。若横向问题占主导，明确本轮x向路线的限制，不更改横向边界来取得通过。

### S2.2 在32单元限制内筛选两套嵌套网格

**做什么：** 当前 `CartesianTopology` 明确拒绝超过32单元，且几何积分按固体与压力切分的并集展开。因此实际GPU路线维持最多32单元。

预登记最多2套新x向分布：每套粗网格16×1×1，细网格将粗网格各x段二分得到32×1×1。建议候选为左右对称的几何渐变，半域8段，从边界到中点宽度按 `1:r:…:r^7`，`r∈{4,5}`，再归一化覆盖原半域。先生成纯拓扑与矩阵，不能看实际动态结果后继续调r。原均匀二分的16/32对照保留。

用于诊断的64/128单元只允许在新的**CPU小矩阵参考模块**中构建：它须独立实现有界拓扑或显式注入接口，先复现原16/32结果，不修改旧32单元构造器、不全局monkeypatch。64/128来自每套32网格继续嵌套二分，完整RT0、完整非对角迁移率、全部边界语义一致，不能用一维标量模型代替。

**为什么：** 将已有单元集中在薄层，可改善梯度而不增加大型耦合的单元上限。更细的小矩阵是可负担的参考，但不自动获得实际GPU实现资格。

**如何验收：** `S2/grid-design.json`固定全部cuts及哈希；体积、面方向、内部面抵消、边界覆盖、H对称正定与压力源量通过。CPU新模块在旧16/32上复现原矩阵；构造前记录各候选实际交集点数与总内存估计。超资源则拒绝该候选，不放宽保护。

### S2.3 用精确时间参考分开空间误差与时间误差

**做什么：** 固定骨架下，从原混合方程消去流量，保留完整空间矩阵：

\[
C\dot p+Lp=b,\qquad L=BH^{-1}B^T.
\]

沿用增广矩阵指数，同时求压力和累计边界量；区间流量由累计量差除以区间长度求得。先检查64/128参考的相互差异，再评估新16/32，不把某一细网格自行标成真解。

时间方案最多2种：原均匀16步；若薄层导致中点时间法早期误差或振荡，再试预登记 `t_n=T(n/16)^3` 的16步方案。各自细方案均逐区间二分成32步。所有比较包含第一个区间，禁止删掉启动层；不能以压力裁剪处理负压。针对每套网格，在看实际耦合轨迹前登记最终时间表。

选型先看压力、每面／每方向流量、累计排水和非负压力，再看最低成本；新32相对可信细参考须满足工程预算，64/128差异须不超过对应预算25%，时间离散差异也不超过25%。这25%用于给参考误差留余量，不是把最终场景要求改成更严的物理门槛。

**为什么：** 变细的边界单元会引入更快压力时间尺度；空间改善可能同时增加时间刚性。只加网格、不查时间，会再次混淆误差。

**如何验收：** `S2/fixed-skeleton-reference.json`分别给出参考可靠性、空间差异和时间差异；两套候选都不满足时登记`reference_limited`或`time_limited`，停止实际新耦合分支。本轮不增加第三网格方案、256单元参考或更多时间方案。固定骨架资格不可写为实际耦合资格。

### S2.4 仅对一套胜出方案做四个实际短窗

**做什么：** 对最终选定的新16/32单元，各跑选定16/32时间步，共最多96步。先完成16单元的时间对照，通过后再运行32单元。采用BASE已通过的设备RT0，当前F与H始终对应，仍用一般LU和原真实残差。

每支从同一个物理静止初态、均匀0.2Pa及零历史重新建立所属网格状态；按本格容量构造初始含量。不把旧网格检查点改标签后恢复到新网格。每个案例固定协议、所有权和JSON安全身份，计划一支在第2步停下并在新进程恢复，前2步计入主轨迹。

先登记五个共同物理观测时刻；若它们不在选定非均匀时间表上，直接选择共同时间节点并登记，而不是插值制造动态证据。至少两个不相邻时刻达到原位移或速度可观测阈值；未达到则如实记为未观测，不提高载荷补过门槛。

**为什么：** 固定骨架不能覆盖固体变形、压力功和非线性迭代；真实短窗是新网格接入资格的必要证据。

**如何验收：** 四个案例的`summary.json`分别报告完整性、真实残差、最小J、质量、分账能量、压力功、非负耗散、RSS及GPU峰值。两网格时间比较各自通过，进程恢复和检查点完整。单支失败定位普通原因后在4次余量内修复；不能反复启动掩盖成本。

### S2.5 做保守跨网格比较，区分改进与认证

**做什么：** 在相同细时间表上比较新16／新32。压力按体积平均、含量按交叠份额求和，流量按共同定向面累计，并验证：

\[
B_{16}R_z=R_cB_{32}.
\]

复用BASE的 `grid_transfer.restriction` 只处理满足条件的嵌套网格。旧网格与新分布内部面可能不重合：压力／含量可用体积交叠，边界物理面可比较累计量；不能把不共面的内部流量向量直接相减，也不能强行绕过现有保守限制校验。

比较骨架／总应力、位移、速度、反力、压力、面流量、累计排水；新网格与旧已知欠分辨结果的差异用于解释改进，不要求新结果迁就旧错误。实际新16/32相互比较才是本轮双网格工程门槛。

**为什么：** 使用错误的网格限制会伪造通量误差；固定骨架参考与实际双网格资格也需要分别记录。

**如何验收：** `S2/coupling-decision.json`分开记录固定骨架、实际时间、实际网格、守恒、可观测性和恢复。实际网格仍未通过时保留limited，不因CPU参考通过而改写。即使通过，也只授予此x向网格、参数和短窗内经验资格，横向三维精度、标定与完整周期仍未认证。

## 7. S3：只建立一个更短的候选时间参照

### S3.1 登记共同初态与精确窗口

**做什么：** 保持原候选空间、材料、质量、边界和稳定化，从原初态digest开始。固定 `h*=1.220703125e-5s`，窗口为 `[1.075,1.07509765625]s`，比较8步h*与16步h*/2。

若S1没有改变数值实现，原BASE候选256步的前8步就是粗支，经过源码、初态与时刻验证后直接复用；否则新建8步分支。细支始终从同一原初态独立推进，禁止从粗支终态启动。不把重新投影的晚期状态当成已有共同历史。

**为什么：** 先在原窗口最短前缀中得到分辨清楚的局部响应，避免重跑已有完整256步或盲目扩大步数。

**如何验收：** `S3/short-reference-protocol.json`列出初态文件哈希与digest、空间包、步长、8／16时刻、复用理由和新增步数。S1有未定位的数值异常时不运行受影响分支。

### S3.2 按原预算检查时间误差

**做什么：** 输出同节点物理场和同区间反力，按共同口径逐区域比较；保留未经平移的原始输出。质量、能量、完整反力和恢复状态独立检查。最多16个新增细步，必要的粗支8步及4次异常余量计入28次上限。

**为什么：** 此阶段判断的是候选空间自身时间分辨率，不能用候选和正式空间差异代替同空间时间误差。

**如何验收：** `S3/short-reference-comparison.json`的位移、速度、应力、反力都满足工程预算，原残差和能量通过。若某量未过预算，本轮不继续32/64细步；记录该量、区域和时刻。短窗没有足够事件时记`unobserved`，不能宣称事件精度通过。

### S3.3 限定新资格，保留原负面结果

**做什么：** 单独输出`local_prefix_time_passed`、`old_full_window_time_passed=false`、`global_temporal_accuracy=false`。只允许S4使用已分辨前缀内的动力学信息；五点晚期诊断可以解释问题，但不能作为已认证动态训练目标。

**为什么：** 缩短窗口后通过，不等于原 `[1.075,1.078125]s` 误差已经解决，更不等于252步全周期已经准确。

**如何验收：** `S3/reference-scope-decision.json`明确作用域。局部不过则S4不触发；局部通过仍不能更换正式时间表或延伸q5权限。

## 8. S4：满足依赖后，只试一次144函数重分配

### S4.1 先审查静态参考与设计信息

**做什么：** 检查S1解释与S3局部时间结果；复用旧phase-boundary的R4/R5参考、原物理嵌入及参考审计。登记45°、52.5°、60°三个历史设计工况与48.75°历史回归工况，逐区域复查R4/R5差异是否≤对应工程预算25%。

48.75°已经在历史研究中看过，不能标成“全新隐藏集”。本轮不新增大型参考求解；缺少可靠参考就不触发空间设计。

**为什么：** 当前目标是一个有限的机制试验，已有静态通过不能认证动态连续体真解，也不能凭历史测试声称新的泛化能力。

**如何验收：** `S4/design-eligibility.json`逐条列出依赖、参考身份、过去使用情况。任一依赖不足则交付`not_triggered`和原因，0新空间／0新动态步。

### S4.2 固定138个函数，仅设计6个替换方向

**做什么：** 保持原载体、几何、边界、环境空间、总预算144和稳定化含义。只产生一个候选；用完整质量Schur补剔除既有支撑的可表达部分，再在剩余子空间选6个独立方向。评分同时考虑分区应力、完整反力和S1中解释清楚的局部恢复力响应。

候选刚度和能量始终通过完整变换计算：

\[
M_r=P^TMP,\quad K_r=P^TKP,\quad
U_{quad}=\tfrac12\sum_{i,j}q_iK_{ij}q_j.
\]

不得仅按每个函数的对角分数相加，忽略交叉项。训练权重、目标区域、退化阈值在求解前登记，不按48.75°结果回头调候选。

**为什么：** 重叠函数之间的相互作用决定实际表达能力；已有候选的稳定化响应提示仅按静态位移快照评分可能不足。

**如何验收：** `S4/candidate-package.json`及空间包记录144预算、138／6拆分、支撑、映射、独立性与质量秩，证明有实际新子空间。静态方向和局部动态方向来源明确；不更换正式包。

### S4.3 先做零步算子与最多4个静态工况

**做什么：** 按原方法检查完整质量、载体—局部交叉项、边界、能量—内力—切线、CPU/GPU等价与积分充分性。必要时复用M7/M8质量检查，但不得混用材料q5。

依次运行已登记3个设计工况和1个历史回归工况，单模型顺序加载。预登记一个主要改善目标：其误差至少下降10%，且改善大于参考不确定性的2倍；其余区域不能超过工程预算，误差增加不超过 `max(2×参考差异, 0.1×工程预算)`。若目标本来远低于绝对尺度，则不以微小百分比宣布收益。

**为什么：** 先排除空间、质量与静态退化，避免把不合格空间送入动态轨迹。

**如何验收：** `S4/operator-check.json`、`static-comparison.json`分别通过；没有明确收益则保留原空间，不启动第二候选。本轮最多4个新静态求解，不顺带重跑R4/R5。

### S4.4 仅在已分辨前缀做8/16步动力学

**做什么：** 从原正式物理初态，用已有受约束完整质量投影建立新空间初态，记录位移、速度、动能和势能变化；不得复制旧系数或仅改签名。两支从同一个新初态启动，使用S3同一短窗和步长。与旧候选／正式空间比较共同探针，而不是裸系数。

**为什么：** 静态应力改善可能伴随更高频响应或初态能量跳变，需要短动态证据才能评价。

**如何验收：** 新空间自身8/16步时间误差通过，边界、正J、真实残差、能量及事务通过；目标物理量有可分辨改善，其余区域无超预算退化。跨空间仅报告相互差异，不把正式空间当作连续体真解。`S4/space-decision.json`最多授予局部研究资格，不能覆盖正式144空间、252步或旧q5证书。

## 9. S5：重新找热点，最多保留一个性能候选

### S5.1 对当前设备RT0路径做实际剖析

**做什么：** 优先使用S2新完成且稳定的两个真实状态；如果S2没有合格新分支，则使用BASE原16单元实际第1／3步状态，并按既有所有权桥接验证。记录构造、材料／残差、当前几何与体积梯度、RT0、线性求解、场重建、输出和提交。内核计时同步GPU，预热、缓存和文件输出策略单列。

**为什么：** RT0已经显著变快，继续优化原先的热点可能没有端到端收益。

**如何验收：** `S5/profile.json`能解释主要步耗时，性能基线明确是当前设备RT0。只有某可优化环节实测占比≥20%，且存在可保持方程的实现路线，才进入S5.2；否则只交付剖析，不强行新增缓存。

### S5.2 实现一个有边界的候选并做等价检查

**做什么：** 按剖析选择一次优化，例如重复分配的复用或实际占比高的体积梯度缩并；不预先认定哪条一定有效。用实例私有对象和显式身份，不全局替换原算子。重用静态元数据时验证所有权，缓存数值结果时绑定当前状态、几何、规则和材料。

**为什么：** 本轮已见过身份格式导致发布失败；性能改动必须同时考虑存档、回滚和缓存失效。

**如何验收：** 静止、非零制造状态、两个真实状态的相关能量／内力／切线或H/G/V分别等价；JSON身份往返通过；新增峰值内存不突破原保护。变形改变后不能复用旧H；失败时不能残留新缓存和累计账目。

### S5.3 用少量真实A/B步决定保留或否决

**做什么：** 两状态各跑当前基线A与候选B，至少一对双方均包含正常帧输出和提交。比较完整物理状态、原残差、迭代次数与时间；有明显计时波动时最多增加一对复核。必要的失败／恢复计入8次总预算；同源S2证据可覆盖的部分不重复。

**为什么：** 局部核函数更快不代表整步更快，构造开销和内存增长也可能抵消收益。

**如何验收：** 两个状态均无明显退化，中位真实步耗时下降至少5%，且高于实测波动或两个状态的收益差；未做重复不能声称有噪声置信区间。设置开销须在16步内收回。无收益或共享GPU干扰则保留当前设备RT0，`performance-decision.json`记录否决原因。S5之前轨迹仍绑定其运行实现，最终换实现后不得伪称旧轨迹由新实现重算。

## 10. S6：最小回归与可复核交付

### S6.1 按实际改动列测试，不机械重跑旧实验

**做什么：** 形成源码影响表。对新增CPU拓扑、守恒限制、时间表、状态初始化、JSON身份和缓存失效做必要小测试；原32单元构造器及源文件哈希不变。若S1修改了真正的数值公式，追加相应导数和短步对照，不能只测存档。

复用BASE原24项测试、完整日常场景与同源事务证据；新执行数、不同测试数、重复测试数、动态尝试分别记录。最多4步补齐新最终源码的故障／恢复缺口；如修改范围超出本计划预算，停止推广而不是把缺口标成通过。

**为什么：** 测试应覆盖本次实际风险，避免浪费算力，也避免靠继承测试掩盖新接口问题。

**如何验收：** `S6/tests-result.json`、`regression-impact.json`、`fallback-and-restart.json`绑定最终测试源码。错误来源、错误空间／规则／时间表被拒绝；完整恢复包括流体与累计账目。

### S6.2 检查实际默认来源、展示与资格标签

**做什么：** 通过来源解析器零步加载SOLID日常终态，核查252步、质量、原q5证书和活动规则。重绘继承12帧日常动画，独立展示S1分解、边界分区排水、局部时间误差、条件候选和实际性能图。

页面同时标注 `raw_event_status` 与 `engineering_output_status`，保留旧全窗口参照limited、新短前缀资格以及耦合网格资格。显示变形倍率不能用于数值验收。S2未触发时展示小矩阵结果并注明没有新实际轨迹。

**为什么：** 日常动画、局部参照和研究耦合是不同来源、不同适用范围，不能让展示制造“全部认证”的印象。

**如何验收：** `S6/load-check.json`实际加载通过；保存图像人工查看；HTTP资源、GIF解码和JS语法通过。未操作浏览器控件就不声称交互验收。最新可视化CLI必须指向真实生成的新目录，并实际验证服务。

### S6.3 逐项登记、冻结源码和产物

**做什么：** 为本文S0.1—S6.3共25步生成需求审计，使用`passed_scoped / limited / inherited / not_triggered / resource_limited`，每项绑定证据。条件未触发也必须记录原因和0新增工作，不能漏项。更新独立进展文档，保留异常原因和决策，最终概览放在开头。

冻结实际源码、运行时源码快照、最终源码快照、参数、空间、参考、测试、尝试与资源记录；记录性能修改前后轨迹来源。发布只引用实际默认所有者和原q5权限。审计全部祖先、当前源码、快照与产物；封存后不再原位修改。

**为什么：** “最新”必须可以从来源链重建，失败及未触发分支也属于研究成果。

**如何验收：** `requirement-audit.json`覆盖25步，`capability-matrix.json`明确静态／短动态／完整周期、时间／空间、固定骨架／实际耦合资格；实际尝试≤172，新展示帧≤12。最终用户说明包含收益、未解决问题、资源情况、报告链接和已验证CLI；所有“通过”都能指向证据。

## 11. 异常处理与停止规则

| 现象 | 处理与继续条件 |
| --- | --- |
| 路径、JSON类型、身份序列化或明确索引问题 | 在独立分支定位、修复并做最小回归；保留原失败证据，正常继续 |
| 守恒、残差、正J或状态恢复异常 | 停止受影响分支，保存最小复现；查明后在预算内修复，难以定位则limited，不跳过继续推进该状态 |
| 稳定化项大，但导数和变换没有错误证据 | 记录物理投影／高频响应诊断；不删除稳定化、不调阻尼 |
| 64/128小矩阵参考仍不接近 | reference_limited；不把128宣布为真解，不启动更大的实际GPU网格 |
| 边界网格细化后时间振荡 | 用预登记第二档时间方案和精确矩阵参考判断；两档都失败就停止，不裁剪压力或修改边界 |
| 两网格流量差大、质量守恒却很小 | 分别保留守恒通过和网格精度未过，不能互相替代 |
| 局部短参照通过，原全窗口仍失败 | 只开放局部研究资格；不修改旧全窗口／全局标记 |
| 性能收益不足、构造过贵或计时受共享GPU干扰 | 否决或不签收益，保留已合格的BASE设备RT0 |
| 系统盘低于5GiB或内存保护触发 | 按2.2节处理，记录资源受限；不删来源、不放宽保护 |
